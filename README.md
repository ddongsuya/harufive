### 점수·주간 등급

정답 한 개당 1,000점, 시간 보너스는 전체 합계에 최대 99점입니다. **정답 수가 우선이고 같으면 다섯 답 제출 시간의 합계가 짧은 이용자가 앞섭니다.** 화면 점수가 같아도 정확한 밀리초를 비교합니다. 정답 수와 시간이 모두 같으면 공동 순위이며 정답 0개끼리는 시간과 관계없이 공동 순위입니다.

- `db/schema.ts`, `drizzle/`: 실제 D1 스키마와 배포용 생성 SQL. 요청 처리 중 테이블을 만들지 않습니다.
- `legacy/v040/`: 이전 브라우저 프로토타입 보관과 서버의 순수 출제·점수 함수 출처. 공개 디렉터리가 아닙니다.

인증 식별자는 내부에만 두고 공개 프로필과 랭킹에는 별도 무작위 ID·닉네임·장착 모습·성적을 사용합니다. 서버 API는 인증되지 않으면 401, 다른 출처의 변경 요청이면 403을 반환합니다. 점수·코인·이용자 ID·클라이언트 측정 시간을 요청 필드로 받을 수 없습니다.

동시 수정은 계정 revision 비교와 트랜잭션 전용 토큰으로 제어합니다. 결과·코인·원장·요청 영수증이 함께 확정되거나 함께 취소됩니다. 주간 마감 레코드와 순위 스냅샷도 같은 배치에서 확정하며, 마감 뒤 지연된 전주 최종 제출을 차단합니다. D1 읽기는 `first-primary` 세션을 사용합니다.

답 본문을 모두 수신한 시각을 먼저 저장한 뒤 인증·계정 확인·요청 제한 DB 조회를 시작합니다. 점수에는 그 조회 지연을 더하지 않습니다. 반대로 답안을 늦게 스트리밍하는 동안은 시간이 계속됩니다. 인터넷 왕복과 문항 전달 지연이 완전히 제거된 정밀 타이밍은 아니며 실제 기기·네트워크에서 확인해야 합니다.

서버로 옮겼다는 사실만으로 다중 계정·자동 풀이·외부 도움을 모두 막는 것은 아닙니다. 실시간 부정 이용 탐지, 운영자 문항 관리, 대규모 트래픽 시험은 미구현 또는 미검증입니다.

공개 출시 전 필요한 운영 정보, 등급분류 문의 초안, 아동·청소년 범위, 실제 개인정보처리방침 작성 입력, 광고와 결제의 도입 순서는 [정식 공개 준비 문서](docs/release-readiness-v050.md)에 정리했습니다. 임시 운영자·이메일·법적 완료 상태를 만들어 게시하지 않았습니다.

## 개발·검증·배포

Node 22.13 이상과 저장소의 공식 설치 스크립트를 사용합니다. 로컬 의존성 설치는 `npm run install:ci`, 정적 검사 `npm run check`, 검증 `npm test`, 빌드 `npm run build`입니다. 설치·빌드는 Sites의 제공 도구로 실행할 수도 있습니다. 모의 DOM 테스트는 파일별 Node 프로세스 격리가 필요합니다. 제한된 실행 환경에서 파일 단위 결과만 표시되면 개별 파일을 `node tests/server-http.test.mjs`처럼 직접 실행해 실제 케이스를 확인합니다.

스키마를 바꾸면 `npm run db:generate` 후 생성 SQL과 메타데이터를 검토합니다. 이미 적용한 마이그레이션 파일은 고치지 않고 새 마이그레이션을 추가합니다. 실제 배포는 같은 Sites 프로젝트의 소스를 먼저 저장하고 그 정확한 소스에서 만든 Worker 빌드와 SQL 마이그레이션으로 진행합니다. `.openai/hosting.json`의 프로젝트 ID와 `DB` 바인딩을 유지합니다.

새 버전에서 문제가 생기면 공개 범위를 넓히지 않고 정상 버전 재배포를 먼저 검토합니다. **코드 재배포가 DB를 되돌리는 것은 아닙니다.** DB 변경을 이미 적용한 배포라면 이전 코드의 스키마 호환성을 먼저 확인하며, 이전 브라우저 프로토타입으로의 복귀가 새 서버 기록을 가져오는 경로는 아닙니다.

`GET /api/health`는 버전과 13개 테이블·인증 마이그레이션 준비 상태만 반환하며 이용자 자료는 내보내지 않습니다. 인증되지 않은 `GET /api/game/bootstrap`은 로그인 필요 응답을 반환합니다. 소유자 비공개 환경에서는 앞단의 접근 제어가 이 요청들에도 적용될 수 있습니다.

### 검증 범위

새 서버 검증은 배포에 사용하는 정확한 SQL 마이그레이션을 실제 SQLite에 적용합니다. 최종 답안 중복·동시 구매·SQL 오류 전체 롤백·주간 마감 경쟁·기억 노출·타 계정 접근·최근 조회와 전체 기록·상위 100명과 본인 별도 순위를 확인합니다.

HTTP 검증은 실제 Request/Response와 스트리밍 본문으로 인증·출처·필드·크기·요청 제한·서버 처리 지연 제외를 검사합니다. 화면 검증은 실제 공개 컨트롤러를 실행하며 응답 유실·재시도·401·429·기억 노출 종료·상점과 공식/연습 완주를 실제 HTTP 서비스·SQLite까지 연결합니다.

기존 8개 파일의 테스트는 `legacy/v040/` 프로토타입 회귀 검증입니다. 그 안의 가상 랭킹·광고 체험 테스트가 새 서비스에도 해당하는 것은 아닙니다. 새 서비스는 `server-game`, `server-http`, `release-ui`, `auth-server`, `social-ui` 테스트가 담당합니다. 인증 테스트는 로컬에서 서명한 실제 RS256 토큰과 실제 SQLite SQL로 검증하며 제공자 서버와의 실제 사용자 로그인 검증은 아닙니다.

현재 환경에는 Sites에서 지원하는 브라우저 제어 기능이 없어 **실제 휴대폰 화면의 겹침·터치·로그인 왕복·캔버스 출력·소리 청음·알림 수신은 검증하지 못했습니다.** 실제 D1 운영 환경의 다중 지역 지연·대규모 트래픽 성능도 SQLite 검증과 별개입니다. 최종 실행 결과와 발견·수정한 결함은 [v0.5.1 검증 기록](docs/release-verification-v051.md)에 남깁니다.

`scripts/export-standalone.mjs`는 보관한 **v0.4.0 프로토타입**만 단일 HTML로 내보냅니다. v0.5.x 계정·서버 게임의 오프라인 내보내기가 아닙니다. 도트 그림의 `scripts/avatar-pixel-qa.mjs`는 `public/game/avatar.js`를 사용합니다. 그림 설계는 [도트 리디자인 문서](docs/pixel-art.md), 기존 소리와 캘린더 설명은 [소리 문서](docs/audio.md)와 [알림 문서](docs/reminders.md)를 참고하세요.
