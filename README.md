## 현재 수익화 결정

하루다섯은 **무료 플레이와 광고 수익만**을 목표로 합니다. 현금 캐릭터·꾸미기 판매, 코인 충전, 구독, 유료 광고 제거권·후원은 제외합니다. 기본 토끼와 플레이로 획득하는 게임 코인 상점은 유지합니다. 실제 광고는 아직 연결하지 않았습니다. 가입·이용 대상은 **만 14세 이상**으로 변경했습니다. 이전의 아동 포함 B안을 대체하며 신규 아동 가입·보호자 연결은 제외합니다. 실제 연령 확인·가입은 아직 닫혀 있고 기존 가족의 개인정보 권리 행사는 보존합니다. [연령 정책](docs/age-eligibility.md)을 따르며 유료 본인인증을 필수 계약으로 확정하지 않습니다. [광고 수익 전용 운영 방향](docs/ad-only-policy.md)을 따릅니다.

## Codex 로컬 개발 후속 작업 (2026-10-20)

- 사용자 승인에 따라 개발 저장소 [ddongsuya/harufive](https://github.com/ddongsuya/harufive)를 **Private**로 전환하고 소스 업로드를 완료했다. 원본은 `main`, 후속 개발 소스는 `codex/local-standalone-foundation`에 있으며 [Draft PR #1](https://github.com/ddongsuya/harufive/pull/1)에서 검토할 수 있다. PR 병합과 서비스 배포는 완료하지 않았다.
- GitHub 연결 도구가 같은 파일 트리를 별도 커밋으로 가져왔으므로 로컬과 원격 커밋 ID는 다르다. 이후 원격 브랜치 이력을 기준으로 이어가며 기존 로컬 이력을 강제 push하지 않는다. 정확한 대응과 과거 Sites 배포 차단 이력은 [인수인계](CODEX_HANDOFF.md#11-codex-후속-작업--2026-10-20)를 따른다.
- Windows + Node 24.13.0에서 인계 원본 156개 테스트·검사·빌드를 재현했다. 독립 환경 1단계는 164개, 정보 관리 UI를 추가하기 전의 보호자 서버 단계는 **230개 테스트·타입 검사·기존 Sites 빌드 통과**를 확인했다. 정보 관리 UI 단계는 271개, 기존 계정 재인증 단계는 342개, 독립 Worker 준비 단계는 **349개 전체 테스트·구문/타입 검사·기존 5단계 빌드와 별도 Worker dry-run 통과**를 확인했다. 만 14세 이상 정책 단계에서는 전체 **353개 테스트·구문/타입 검사·Worker dry-run 통과**를 확인했다. 세부 결과와 과거 검증 범위는 [Codex 검증 기록](docs/codex-verification-2026-10-20.md)을 따른다.
- 최소 런타임은 Node 22.16.0 이상인 22.x 또는 24 이상이다. `StatementSync.columns()`를 사용하므로 이전 22.13 표기를 수정했고 패키지 버전은 변경하지 않았다. Node 22.16.0 자체의 전체 실행 검증은 아직 하지 않았다.
- `npm run db:local`로 별도 SQLite DB를 준비하고 `npm run dev:local`로 **http://127.0.0.1:5174**에서 현재 화면을 확인할 수 있다. 재시작해도 로컬 DB를 보존한다. 기본 `npm run dev`는 기존 Sites 개발 경로다.
- 독립용 `server/standalone-http.mjs`는 기존 플랫폼 인증 헤더·예약 로그인 경로를 사용하지 않고 자체 세션만 인정한다. 기본 실행기는 키가 설정돼도 소셜 OAuth 시작·콜백을 열지 않으며 `HARU_REGISTRATION_OPEN=true`가 전달되어도 신규 가입을 닫는다. 별도 연결용 시험본만 서버에서 기존 계정 로그인을 선택하며 새 가입은 허용하지 않는다.
- 로컬 미리보기는 실제 소셜 키·로그인을 대신하지 않는다. 테스트 계정을 자동 생성하지 않으며 로그인 버튼은 준비 상태를 표시한다. 게임 로직은 서버 코드·SQLite 통합 테스트로 검증했다.

실행 방법과 연결 범위는 [로컬 개발 안내](docs/local-development.md), 실제 결과는 [Codex 검증 기록](docs/codex-verification-2026-10-20.md), 보호자 기능의 현재 구현 범위는 [동의·삭제 구현 상태](docs/guardian-implementation-plan.md)와 [운영 연결 안내](docs/privacy-operations.md)를 따른다. 기존 운영 사이트를 변경하거나 독립 호스팅에 배포한 작업은 아니다.

## 인증 설정 점검

최신 후속 작업에서 비밀번호 보호 뒤 기존 계정의 로그인·기록 저장을 연결하는 [별도 시험본](docs/connected-preview.md), [이용·개인정보 안내 초안](docs/service-policy-draft.md), 모바일 답안 버튼 가림과 화면 초점 수정을 추가했다. 전체 **396개 테스트·검사·빌드**와 실제 로컬 Worker/D1 검증을 통과했다. 사용자 보고에 따른 [개발자 앱 생성 상태](docs/developer-app-setup.md)는 실제 서버 연결과 구분한다. 원격 Worker·DB·첫 가입·실제 제공자 로그인은 아직 미완료다.

`npm run auth:check`로 실제 키 없이 누락 설정과 준비 상태를 확인할 수 있다. 허용된 프로세스 환경값만 검사하며 비밀값 출력·환경 파일 자동 읽기·네트워크·DB 변경을 하지 않는다. 설정 형식과 실제 로그인·재인증 지원은 구분하고 전체 출시 준비는 false로 유지한다. [인증 연결 점검](docs/auth-connection-checklist.md)을 따른다.

Google은 공식 안내상 계정 강제 재인증 요청을 지원하지 않아 해당 재인증 경로를 차단했다. 일반 로그인·계정 연결 코어는 유지하며 카카오·네이버의 실제 재인증도 아직 검증하지 않았다. 본인 철회·삭제는 준비되지 않은 복구 경로를 우회하지 못하도록 화면과 HTTP에서 함께 막고, 본인 조회·내보내기와 기존 가족의 권리 행사는 보존한다.

## 독립 Worker와 월 운영 예산 준비

- `npm run build:worker`로 공개 파일만 묶어 업로드 없는 Worker 빌드 검사를 수행한다. `db:worker`·`dev:worker`는 기존 미리보기와 분리된 PC 내부 D1 및 8787 서버를 사용한다. 실제 로컬 마이그레이션·DB 상태·공개 14개 파일·비공개 경로 차단을 확인했다.
- 설정은 로컬 시험용 D1 ID, 비공개 원점 제한, 닫힌 가입·로그인·재인증을 유지한다. 실제 Cloudflare 계정·DB·도메인·결제·운영 예약 작업을 연결하지 않았다. [독립 Worker 실행](docs/standalone-worker.md)을 따른다.
- 사용자는 **사업자등록 전 상태**, 예산은 **도메인·서버·인증을 포함해 월 3만 원 이내**다. 현재는 로컬 무료 검증을 유지하고 Free 호스팅 후보를 검토한다. Paid의 원화 강제 상한과 필요한 연령 확인 방법·미등록 개인 계약 조건은 미확인이다. 과거 보호자 확인 요금 조사는 필수 계약이 아닌 참고 기록이다. 공개 가격·연간 도메인 결제·조건은 [예산 검토](docs/hosting-budget.md)에 구분했다.

## 기존 가족·본인의 정보 관리 구현

- 서명된 보호자 확인 결과에서 신원·성인 여부·관계·동의 항목과 문구 버전을 각각 검사한다. 원문 증빙·확인 토큰·연락처를 DB에 보관하지 않는다.
- 승인 재사용, 다른 가족 접근, 만료 뒤 승인, 로그아웃 뒤 민감한 요청 처리를 차단한다. 민감한 API는 서명된 제공자 토큰의 실제 인증 시각(`auth_time`)을 기록한 `authenticated_at`이 최근 15분 이내인지 DB 처리 시점에도 검사한다. 세션 생성·토큰 발급 시각으로 대신하지 않으며 기존 세션의 증거 없는 값은 NULL로 보존한다.
- 철회·삭제 요청은 로그인과 게임 저장을 차단한다. 답안·구매·프로필 생성·요청 제한·순위 집계에도 현재 계정 상태를 적용한다.
- 삭제는 명시적인 서버 보관 정책이 없으면 대기한다. `npm run privacy:maintain`은 기존 로컬 DB의 만료 요청 정리와 삭제 대기 확인을 한 번 실행하며 운영 예약 작업을 설정하지 않는다.
- `#privacy`의 **나의 정보 관리** 화면에서 본인 기록 다운로드, 서버가 확인한 연결 아동 목록·상태, 아동 기록 다운로드·동의 철회·삭제 요청을 처리하도록 연결했다. 철회·삭제는 대상과 영향을 보여 주는 확인창을 거치며 접수·대기·현재 DB 삭제 완료를 구분한다.
- 계정 상태의 공개 `playerId`를 게임 화면과 대조한다. 아동·보호자 GET 목록과 변경 요청에는 `X-Haru-Account` 문맥을 전달하고, 다운로드 직전에도 계정·문맥·선택한 아동을 다시 확인한다. 탭 숨김·화면 이동·로그아웃·계정 변경 시 개인 목록과 확인창을 지우며 늦은 응답을 표시하지 않는다.
- 연결이 끊겨 접수 여부가 불확실하면 변경 요청을 자동 재전송하지 않고 **현재 상태 다시 확인**으로 서버 상태를 조회한다. 본인 탈퇴·삭제는 폐쇄 계정의 권리 행사·복구 경로가 준비되지 않아 버튼과 HTTP에서 모두 차단한다.
- `#guardian`은 만 14세 이상 이용 정책과 기존 가족의 권리 행사 경로를 안내한다. 신규 보호자 요청·재발급·승인과 아동 연결을 열지 않는다. 실제 연령 확인·일반 가입·제공자 인증, 폐쇄 본인 계정의 후속 권리 행사와 운영 예약 삭제는 미완료다.

기존 활성 계정에는 **최근 본인 확인** UI와 계정·세션·연결 로그인 정보를 고정한 재인증 경로를 준비했다. 성공 시 기존 세션을 교체하고 정보 관리 권한을 다시 조회한다. 취소·화면 이동·계정 변경 시 응답을 버리며 이전 삭제 요청을 자동 실행하지 않는다. 실제 제공자 왕복은 미검증이고 독립 서버의 `reauthEnabled:false`를 유지한다. [재인증 구현과 연결 조건](docs/reauthentication.md)을 따른다.

앱 내 데스크톱 브라우저 854×801에서 로그인 전 `#guardian`·`#privacy` 안내, 준비 중 버튼의 비활성, 화면 전환을 확인했고 콘솔 경고·오류는 없었다. 실제 기기와 로그인한 실계정의 관리 화면은 미검증이다. 최종 자동 검사 결과는 [개발·검증 기록](docs/codex-verification-2026-10-20.md)에 기록한다. `guardianReady=false`, 신규 가입 차단을 유지한다.

문의 메일은 로그인 전 화면·내 정보·출시 안내에 반영했습니다. 문의 수신·답변 시험과 실제 제공자·모바일·운영 환경 검증은 별도로 남아 있습니다.

- **기존 개발 계정:** v0.5.1이 배포된 뒤 처음 접속하면 ChatGPT 로그인 수단을 한 번 선택합니다. 게임 내부의 명시적 선택 후 기존 Sites 로그인 경로로 이동합니다. 기존 서버 기록의 ID·코인·캐릭터는 다시 만들거나 바꾸지 않습니다. 비공개 개발 환경의 소유자는 서버에서 확인한 이메일의 제한된 허용 목록으로 첫 테스트 계정을 만들 수 있습니다. 이 인증용 허용 설정과 이번에 사용자가 지정한 공개 문의 연락처는 목적이 다르며, 같은 이메일을 쓰더라도 문의 주소를 안다는 이유로 시험 계정 접근 권한을 얻는 것은 아닙니다.
- **다른 로그인 추가:** 내 정보 → 로그인 연결 → 제공자에서 본인 인증 → 같은 게임 계정에 연결합니다. 다른 게임 계정에 이미 연결된 로그인은 충돌로 처리합니다. 이메일이 같아도 자동 병합하지 않습니다.
- **인증과 세션:** 세 제공자 모두 서버 Authorization Code + OIDC + S256 PKCE를 사용합니다. 검증된 issuer·client ID·subject 조합으로 계정을 찾습니다. RS256 서명·issuer·audience·nonce·만료·발급 시각을 검증하며, 외부 공급자 토큰은 게임 화면이나 저장소에 보관하지 않습니다.
- **로그아웃과 만료:** HttpOnly·Secure 쿠키와 서버 세션을 사용합니다. 소셜 세션은 7일 후 만료되며, 쿠키가 없어져도 다른 ChatGPT 계정으로 자동 전환하지 않습니다. 계정당 세션은 최대 5개입니다. 로그인 교환 중 취소·로그아웃과 늦게 도착한 응답도 서버의 1회 처리 상태로 제어합니다.
- **현재 비활성:** OAuth 앱 키와 실제 로그인 왕복 확인이 없으므로 세 제공자의 준비 완료를 주장하지 않습니다. Google/Naver/Kakao 실제 키를 등록하기 전에는 시작 API도 설정 부족을 반환합니다.

Sites에서 인증용 이메일·이름을 전달받을 수 있지만 게임 DB에는 이를 저장하지 않습니다. Google OIDC는 `openid email` 권한을 요청해 이메일 claim을 수신한 뒤 게임 데이터에 저장하지 않습니다. Kakao/Naver는 `openid`만 요청합니다. 이메일을 저장하지 않는 것과 조회하지 않는 것은 다르며, 인증·호스팅 업체의 자체 처리는 개인정보 안내에서 별도로 다룹니다.

서버 환경 변수의 키 이름은 `.env.example`, 기존 준비 주소의 콜백 예시와 콘솔 설정은 [소셜 로그인 준비 문서](docs/social-login-launch.md)에 있습니다. 정식 호스팅·도메인을 확정한 뒤 실제 콜백과 제공자 심사를 마무리합니다. 실제 비밀값은 소스·브라우저·문서에 기록하지 않습니다. `HARU_REGISTRATION_OPEN=true`는 연령·동의 검증을 대신하지 않으므로 현재 `false`를 유지합니다.

## 게임 규칙

### 출제와 기억 문제

논리·수리·공간·언어·기억·관찰 중 하루 다섯 분야를 1~5단계로 풉니다. 여섯 날짜를 주기로 분야 위치가 순환합니다. 같은 날짜의 분야·단계 구조는 같지만, 각 문항은 독립된 무작위 값으로 생성하고 서버에 스냅샷을 저장합니다. 재접속이나 닉네임 변경으로 배정 문제를 다시 뽑을 수 없습니다.

문항은 **6분야 × 5단계의 30개 변형 템플릿**을 사용합니다. 변형은 유한하며 다른 사람과 일부 내용이 겹칠 수 있습니다. 모든 문항이 무한히 새롭다거나 변형별 실제 난이도가 같다고 보장하지 않습니다. 기존 문항 검증은 정답의 논리적 일관성을 다루며 실제 이용자의 정답률·풀이 시간에 따른 난이도 보정은 남아 있습니다. 게임 기록은 검증된 IQ 검사 점수가 아닙니다.

기억 문제는 준비 → 고정 시간 배열 노출 → 답변 단계입니다. 준비와 고정 노출 시간은 점수 시간에서 제외합니다. 배열 노출을 시작한 뒤 다시 접속해도 종료 시각은 늘어나지 않습니다. 종료 후 서버는 이전 배열을 다시 응답하지 않습니다. 일반 문제와 기억 문제의 답변 단계에서는 메뉴 이동·새로고침·화면 이탈·연결 끊김 중에도 시간이 계속됩니다.

도전은 한국시간 자정에 마감합니다. 그때까지 끝내지 못한 시도에는 공식 완료 점수와 20코인을 주지 않습니다. 연결 문제로 완료 여부가 불확실하면 같은 요청 ID로 재확인할 수 있습니다.

### 점수·주간 등급

정답 한 개당 1,000점, 시간 보너스는 전체 합계에 최대 99점입니다. **정답 수가 우선이고 같으면 다섯 답 제출 시간의 합계가 짧은 이용자가 앞섭니다.** 화면 점수가 같아도 정확한 밀리초를 비교합니다. 정답 수와 시간이 모두 같으면 공동 순위이며 정답 0개끼리는 시간과 관계없이 공동 순위입니다.

주간 점수는 한국시간 월요일~일요일의 전체 정답 수와 전체 시간을 합산해 다시 계산합니다. 시간 보너스는 한 주에 한 번 붙이며 일별 보너스를 더하지 않습니다. 월요일 이후 첫 서버 요청에서 마감된 주의 전체 참가자 순위를 동결하고, 각 계정의 다음 조회에서 확정 보상을 한 번 반영합니다. 지난주 확정 배지는 다음 주에 표시합니다. 별도 시각 예약 작업을 실행하는 구조는 아닙니다.

실제 참가자 수에 기존 등급 백분위 기준을 적용합니다. 참가자 수가 매우 적으면 상위 등급을 받기 어려울 수 있습니다. 현재는 가상 참가자로 이를 가리지 않으며, 초기 공개 운영의 최소 참가자 수와 등급 보정 정책은 결정이 필요합니다.

### 캐릭터·코인

첫 계정 생성 시 토끼와 시작 코인 180개, 공식 다섯 문제 완주 시 하루 20코인을 제공합니다. 주간 보상은 확정 등급 기준입니다. 이미 보유한 상품을 다시 선택하거나 구매 요청을 반복해도 재차 차감하지 않습니다.

### 소리와 알림

소리는 첫 실행 시 꺼져 있으며 스피커 버튼에서 배경음·효과음을 켜고 각각의 음량을 조절합니다. 문제 풀이 중 배경음은 작아지고 화면을 숨기면 소리를 멈춥니다. 소리로 정답을 미리 공개하지 않습니다.

해설 뒤 알림 제안은 캘린더 반복 일정 파일을 만듭니다. 이용자가 캘린더에 저장하고 알림을 켜야 실제 알림이 울립니다. **웹앱 서버가 푸시를 보내는 기능은 아직 없습니다.** 소리·캘린더 설정은 해당 브라우저에 보관합니다.

## 서버 구조와 신뢰 경계

- `app/`: 한국어 문서와 React 마운트, Sites 인증 도우미, 게임·상태 확인 API.
- `public/game/`: 화면, 공개 카탈로그, 표시용 날짜·통계, 도트 렌더러, 소리, 캘린더, 서버 전송 모듈. 문제은행과 채점 로직을 포함하지 않습니다.
- `server/game-service.mjs`: 인증 계정별 출제·진행·채점·주간 정산·구매·내보내기.
- `server/http.mjs`: HTTP 메서드·동일 출처·JSON 필드·4KiB 본문 크기 검증, 계정별 분당 120회 요청 제한, 오류와 캐시 헤더. 변경·내보내기에 `X-Haru-Player`를 요구하고 현재 인증 계정의 공개 ID와 비교해 예전 탭이 다른 계정에 요청을 적용하는 것을 막습니다.
- `server/auth-service.mjs`, `app/api/auth/[...segments]/route.ts`: 세 제공자 인증·계정 연결·세션·동일 출처 로그인/로그아웃. Sites 자체의 예약된 인증 경로는 유지합니다.
- `db/schema.ts`, `drizzle/`: 실제 D1 스키마와 배포용 생성 SQL. 요청 처리 중 테이블을 만들지 않습니다.
- `legacy/v040/`: 이전 브라우저 프로토타입 보관과 서버의 순수 출제·점수 함수 출처. 공개 디렉터리가 아닙니다.

인증 식별자는 내부에만 두고 공개 프로필과 랭킹에는 별도 무작위 ID·닉네임·장착 모습·성적을 사용합니다. 서버 API는 인증되지 않으면 401, 다른 출처의 변경 요청이면 403을 반환합니다. 점수·코인·이용자 ID·클라이언트 측정 시간을 요청 필드로 받을 수 없습니다.

동시 수정은 계정 revision 비교와 트랜잭션 전용 토큰으로 제어합니다. 결과·코인·원장·요청 영수증이 함께 확정되거나 함께 취소됩니다. 주간 마감 레코드와 순위 스냅샷도 같은 배치에서 확정하며, 마감 뒤 지연된 전주 최종 제출을 차단합니다. D1 읽기는 `first-primary` 세션을 사용합니다.

답 본문을 모두 수신한 시각을 먼저 저장한 뒤 인증·계정 확인·요청 제한 DB 조회를 시작합니다. 점수에는 그 조회 지연을 더하지 않습니다. 반대로 답안을 늦게 스트리밍하는 동안은 시간이 계속됩니다. 인터넷 왕복과 문항 전달 지연이 완전히 제거된 정밀 타이밍은 아니며 실제 기기·네트워크에서 확인해야 합니다.

서버로 옮겼다는 사실만으로 다중 계정·자동 풀이·외부 도움을 모두 막는 것은 아닙니다. 실시간 부정 이용 탐지, 운영자 문항 관리, 대규모 트래픽 시험은 미구현 또는 미검증입니다.

| `auth_oauth_transactions` | state·브라우저 연결·nonce 해시, 10분간 유효한 PKCE verifier, 연결 의도·계정·1회 처리 상태 |
| `auth_rate_limits` | 제공자별 시작/콜백 요청 수. 고정된 6개 버킷만 사용 |

일반 화면에는 최근 90일의 완료 기록을 최대 90개씩 제공하고 누적 일수·정답 수는 전체 DB에서 계산합니다. **조회 범위 90일이 자동 삭제 기간을 뜻하지 않습니다.** 전체 기록은 현재 서버에 유지되며 본인 내보내기에 포함됩니다. 철회·삭제 접수와 정책이 있는 경우의 현재 DB 삭제는 서버에 구현했습니다. 실제 보유기간, 최소 폐쇄 기록의 정리, 운영 예약 실행·백업 반영 절차는 운영 주체와 함께 정하고 연결해야 합니다. D1 운영 백업 복구 실습은 아직 수행하지 않았습니다.

공개 출시 전 필요한 운영 정보, 등급분류 문의 초안, 아동·청소년 범위, 실제 개인정보처리방침 작성 입력, 광고 도입과 현금 상품 제외 방향은 [정식 공개 준비 문서](docs/release-readiness-v050.md)에 정리했습니다. 임시 운영자·이메일·법적 완료 상태를 만들어 게시하지 않았습니다.

## 개발·검증·배포

Node **22.16.0 이상인 22.x 또는 Node 24 이상**(Node 24 권장; 23.x 제외)과 저장소의 공식 설치 스크립트를 사용합니다. 로컬 의존성 설치는 `npm run install:ci`, 정적 검사 `npm run check`, 검증 `npm test`, 빌드 `npm run build`입니다. 설치·빌드는 Sites의 제공 도구로 실행할 수도 있습니다. 모의 DOM 테스트는 파일별 Node 프로세스 격리가 필요합니다. 제한된 실행 환경에서 파일 단위 결과만 표시되면 개별 파일을 `node tests/server-http.test.mjs`처럼 직접 실행해 실제 케이스를 확인합니다.

스키마를 바꾸면 `npm run db:generate` 후 생성 SQL과 메타데이터를 검토합니다. 이미 적용한 마이그레이션 파일은 고치지 않고 새 마이그레이션을 추가합니다. 실제 배포는 같은 Sites 프로젝트의 소스를 먼저 저장하고 그 정확한 소스에서 만든 Worker 빌드와 SQL 마이그레이션으로 진행합니다. `.openai/hosting.json`의 프로젝트 ID와 `DB` 바인딩을 유지합니다.

새 버전에서 문제가 생기면 공개 범위를 넓히지 않고 정상 버전 재배포를 먼저 검토합니다. **코드 재배포가 DB를 되돌리는 것은 아닙니다.** DB 변경을 이미 적용한 배포라면 이전 코드의 스키마 호환성을 먼저 확인하며, 이전 브라우저 프로토타입으로의 복귀가 새 서버 기록을 가져오는 경로는 아닙니다.

`GET /api/health`는 버전과 18개 테이블·인증 마이그레이션 준비 상태만 반환하며 이용자 자료는 내보내지 않습니다. 인증되지 않은 `GET /api/game/bootstrap`은 로그인 필요 응답을 반환합니다. 소유자 비공개 환경에서는 앞단의 접근 제어가 이 요청들에도 적용될 수 있습니다.

### 검증 범위

새 서버 검증은 배포에 사용하는 정확한 SQL 마이그레이션을 실제 SQLite에 적용합니다. 최종 답안 중복·동시 구매·SQL 오류 전체 롤백·주간 마감 경쟁·기억 노출·타 계정 접근·최근 조회와 전체 기록·상위 100명과 본인 별도 순위를 확인합니다.

HTTP 검증은 실제 Request/Response와 스트리밍 본문으로 인증·출처·필드·크기·요청 제한·서버 처리 지연 제외를 검사합니다. 화면 검증은 실제 공개 컨트롤러를 실행하며 응답 유실·재시도·401·429·기억 노출 종료·상점과 공식/연습 완주를 실제 HTTP 서비스·SQLite까지 연결합니다.

기존 8개 파일의 테스트는 `legacy/v040/` 프로토타입 회귀 검증입니다. 그 안의 가상 랭킹·광고 체험 테스트가 새 서비스에도 해당하는 것은 아닙니다. 새 서비스는 `server-game`, `server-http`, `release-ui`, `auth-server`, `social-ui` 테스트가 담당합니다. 인증 테스트는 로컬에서 서명한 실제 RS256 토큰과 실제 SQLite SQL로 검증하며 제공자 서버와의 실제 사용자 로그인 검증은 아닙니다.

현재 환경에는 Sites에서 지원하는 브라우저 제어 기능이 없어 **실제 휴대폰 화면의 겹침·터치·로그인 왕복·캔버스 출력·소리 청음·알림 수신은 검증하지 못했습니다.** 실제 D1 운영 환경의 다중 지역 지연·대규모 트래픽 성능도 SQLite 검증과 별개입니다. 최종 실행 결과와 발견·수정한 결함은 [v0.5.1 검증 기록](docs/release-verification-v051.md)에 남깁니다.

`scripts/export-standalone.mjs`는 보관한 **v0.4.0 프로토타입**만 단일 HTML로 내보냅니다. v0.5.x 계정·서버 게임의 오프라인 내보내기가 아닙니다. 도트 그림의 `scripts/avatar-pixel-qa.mjs`는 `public/game/avatar.js`를 사용합니다. 그림 설계는 [도트 리디자인 문서](docs/pixel-art.md), 기존 소리와 캘린더 설명은 [소리 문서](docs/audio.md)와 [알림 문서](docs/reminders.md)를 참고하세요.
