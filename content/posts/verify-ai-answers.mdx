AI 답변의 가장 어려운 점은 틀린 답이 틀린 티를 내지 않는다는 것입니다. 맞는 문장과 틀린 문장의 말투가 같고, 형식도 같습니다. 그래서 확인하지 않고 넘어가면 오류는 문서에 그대로 남고, 그 문서를 읽은 사람은 오류를 사실로 받아들입니다.

이 글은 AI를 덜 믿자는 이야기가 아닙니다. **어디를 의심해야 하는지**를 미리 정해 두자는 이야기입니다. 의심할 지점을 정해 두면 매번 처음부터 확인하는 것보다 시간이 훨씬 적게 듭니다.

## 환각은 왜 생기는가

대화형 AI는 다음에 올 법한 말을 이어 붙여 문장을 만듭니다. 답이 없거나 애매한 질문에도 같은 방식으로 답하기 때문에, 빈칸이 "모른다"로 채워지는 대신 "그럴듯한 문장"으로 채워집니다. 이것을 흔히 환각이라고 부릅니다.

문제는 환각이 잘 생기는 자리가 정해져 있다는 점입니다. **형식이 정해진 정보**일수록 위험이 큽니다. 틀린 숫자도 단위와 자릿수만 맞으면 맞는 숫자처럼 보이고, 존재하지 않는 논문도 제목과 저자 형식만 갖추면 목록에 넣어도 어색하지 않습니다. 반대로 "이 문장을 더 짧게 줄여 줘" 같은 요청은 틀릴 여지가 거의 없습니다. 어디서 틀리는지 알면, 확인은 그 자리에만 집중하면 됩니다.

<Callout type="note" title="확인해 달라는 요청은 검증이 아닙니다">
"이거 정확해?"라고 다시 물으면 대부분 같은 답이 조금 다듬어진 형태로 돌아옵니다. 모델은 자기가 쓴 문장을 원문과 대조하지 않기 때문입니다. 검증은 같은 모델에게 다시 묻는 일이 아니라, 근거를 직접 여는 일입니다.
</Callout>

## 어디서 자주 틀리는가

| 정보 유형 | 흔히 생기는 일 | 확인 방법 |
| --- | --- | --- |
| 출처·인용 | 존재하지 않는 논문, 제목만 비슷한 문서, 열리지 않는 링크 | 링크를 직접 열어 제목·저자·연도를 확인. 열리지 않으면 그 문장은 근거 없음으로 본다 |
| 수치·통계 | 자릿수·단위·기준 연도가 섞임, 조사 대상이 다른 통계를 인용 | 공식 통계나 보고서 원문에서 같은 숫자를 찾는다 |
| 최신 정보 | 요금, 정책, 지원 프로그램, 제품 기능이 예전 기준으로 설명됨 | 서비스 공식 페이지에서 지금 값을 확인한다 |
| 고유명사·연락처 | 비슷한 이름의 다른 회사, 다른 사람의 번호 | 공식 홈페이지의 안내 정보와 대조한다 |
| 법·규정·약관 | 조항 번호와 내용이 어긋남, 이미 바뀐 규정을 현행처럼 설명 | 국가법령정보센터 같은 원문에서 조항을 직접 읽는다 |
| 코드·API | 없는 함수나 옵션, 버전이 다른 사용법 | 공식 문서와 실제 실행 결과로 확인한다 |
| 요약·인용문 | 원문에 없는 문장을 따옴표로 감싸 인용처럼 표시 | 원문에서 그 문장을 검색해 본다 |

표에서 가장 위험한 줄은 첫 줄과 마지막 줄입니다. 출처와 인용문은 읽는 사람이 "근거가 있다"고 믿게 만들기 때문에, 틀렸을 때 피해가 문장 하나로 끝나지 않습니다.

## 네 단계 검증 루틴

| 단계 | 하는 일 | 걸러지는 것 |
| --- | --- | --- |
| 1. 근거 요구 | 답을 받을 때 문서명·발행기관·연도를 함께 요구한다 | 근거 없는 단정 |
| 2. 원문 대조 | 제시된 근거를 직접 열어 같은 내용인지 확인한다 | 지어낸 출처, 어긋난 수치 |
| 3. 교차 확인 | 다른 도구나 검색으로 같은 사실을 한 번 더 확인한다 | 한 모델의 반복된 오류 |
| 4. 위험 표시 | 사람이 확인해야 하는 문장에 표시를 남긴다 | 조용히 퍼지는 오류 |

1단계만 하면 절반은 걸러집니다. 근거를 요구하면 답이 눈에 띄게 조심스러워지고, 확실하지 않은 부분을 스스로 표시하는 경우도 늘어납니다. 다만 근거를 요구하면 근거까지 지어내는 경우가 있으므로 2단계가 반드시 따라와야 합니다. 이 두 단계를 묶어서 "근거를 붙여 달라"고만 하고 링크를 열어 보지 않으면, 확인한 것처럼 보이지만 확인한 것은 없습니다.

3단계는 같은 모델에게 다시 묻는 방식으로는 되지 않습니다. 검색이 붙은 도구로 원문을 찾거나, 다른 모델에 같은 질문을 던져 답이 갈리는지 보는 편이 낫습니다. 두 답이 갈리면 그 지점이 사람이 확인해야 할 지점입니다.

## 답을 받을 때 붙이는 지시문

매번 다른 지시문을 쓰기보다, 아래 형식을 기본으로 붙이고 필요한 부분만 바꾸는 편이 안정적입니다.

> 아래 형식으로만 답해라.
> 1. 결론: 세 문장 이내
> 2. 근거: 확인 가능한 문서만. 문서명, 발행기관, 발행 연도를 적고, 없으면 "근거 없음"이라고 써라
> 3. 확실하지 않은 부분: 따로 모아서 표시해라
> 4. 내가 직접 확인해야 할 항목: 두세 개만

여기에 한 줄을 더 붙이면 효과가 큽니다. "모르는 것은 추측하지 말고 모른다고 답해라. 대신 확인할 수 있는 방법을 알려 달라." 이 문장이 없으면 빈칸은 언제나 그럴듯한 문장으로 채워집니다.

지시문은 환각을 줄이지만 없애지는 못합니다. 그래서 지시문은 1단계를 편하게 만드는 도구로 쓰고, 2단계는 사람이 직접 하는 일로 남겨 두는 편이 안전합니다.

## 위험도별로 확인 깊이를 정한다

모든 답변을 같은 강도로 확인하면 오래 걸려서 결국 아무것도 확인하지 않게 됩니다. 답이 어디로 가는지에 따라 기준을 나누면 판단이 빨라집니다.

| 쓰임 | 확인 수준 |
| --- | --- |
| 혼자 보는 아이디어, 초안, 목차 | 확인하지 않아도 된다. 다만 그 문장을 그대로 인용하지는 않는다 |
| 사내 공유 문서 | 숫자, 고유명사, 날짜만 원문과 대조한다 |
| 외부로 나가는 메일, 제안서, 공지 | 수치·인용·법 조항 전부 원문 확인. 인용문은 원문에서 복사한다 |
| 계약, 정산, 신고, 의료·법률 판단 | AI 답변을 결정의 근거로 쓰지 않는다. 담당자나 전문가에게 확인한다 |

세 번째 줄에서 자주 놓치는 것이 인용문입니다. AI가 정리한 문장을 따옴표로 감싸 인용하면, 원문에 없는 문장이 상대방의 말로 둔갑합니다. 인용은 원문에서 직접 복사하고, 요약은 요약이라고 밝히세요.

## 확인 시간을 줄이는 습관

- 처음부터 확인 가능한 형태로 요청한다. 나중에 출처를 붙여 달라고 하면 이미 문장이 굳어 있다.
- 확인한 문장에는 표시를 남긴다. 같은 문서에서 같은 숫자를 두 번 확인하는 일이 줄어든다.
- 링크는 열어 본 것만 인용한다. 검색 결과의 제목만 보고 인용하지 않는다.
- 요약에는 원문 위치를 함께 적는다. 페이지 번호나 소제목이면 충분하다.
- 요금·정책·기능처럼 바뀌는 정보는 확인한 날짜를 적어 둔다.

## 5분 체크리스트

- [ ] 숫자에 단위와 기준 연도가 붙어 있는가
- [ ] 인용문을 원문에서 직접 찾아봤는가
- [ ] 제시된 링크를 실제로 열어봤는가
- [ ] 출처의 발행 연도가 지금 판단에 유효한가
- [ ] 확실하지 않은 문장에 표시가 남아 있는가
- [ ] 이 문장이 밖으로 나가도 되는 내용인가

## 자주 하는 실수

- **다시 물어보고 확인했다고 생각한다.** 같은 모델은 같은 답을 반복한다. 원문이나 검색이 필요하다.
- **출처가 있으면 맞다고 본다.** 출처도 지어낸다. 링크를 열어 본 것만 근거로 친다.
- **요약을 원문처럼 쓴다.** 요약은 해석이다. 보도, 계약, 발언을 인용할 때는 원문을 쓴다.
- **한 번 확인한 문서를 계속 믿는다.** 요금과 정책은 바뀐다. 오래된 확인은 확인이 아니다.
- **확인을 한 사람에게 몰아준다.** 누가 무엇을 확인했는지 문서에 남기지 않으면, 아무도 확인하지 않은 것과 같다.

## 정리

AI는 초안을 빨리 만드는 도구로는 충분히 유용합니다. 다만 사실의 최종 책임은 답을 받은 사람에게 남습니다. 위의 두 표, 즉 어디서 자주 틀리는지와 어디까지 확인할지를 저장해 두고, 오늘 쓰는 문서 하나에 그대로 적용해 보세요. 확인 지점을 미리 정해 두면 AI를 덜 쓰게 되는 것이 아니라, 확인하는 시간을 아끼면서 더 편하게 쓰게 됩니다.
