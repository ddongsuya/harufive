## 3. 정식 호스팅 방향

### 현재 Sites와 어린이 대상 서비스

Sites는 13세 미만 또는 적용되는 디지털 동의 연령 미만의 아동을 대상으로 하는 사이트를 허용하지 않는다고 안내한다. 따라서 B안을 위한 정식 서비스는 해당 대상을 허용하는 독립 호스팅을 마련해야 한다. 현재 배포 차단을 해결하는 것만으로 아동 대상 공개 준비가 끝나지는 않는다. [Sites 공식 안내][sites]

### 기술적 1차 후보: 사용자 소유 Cloudflare Workers + D1

현재 서버가 Fetch/Response와 D1을 사용하므로 Workers+D1은 변경량을 줄일 수 있는 후보다. 게임 화면·문제 출제·서버 채점·재화 처리·DB 스키마·소셜 세션 구현을 대부분 재사용하고, 플랫폼에 종속된 인증과 배포 구성을 분리하는 방향을 권한다. 이는 현재 저장소를 검토한 기술적 판단이며 아직 호스팅을 선택하거나 신청한 것은 아니다.

계약 적합성은 별도로 확인해야 한다. Cloudflare의 개인정보처리방침은 고객이 운영하는 앱에 고객의 정책과 법규 준수 책임이 적용된다고 구별하고, Developer Platform 약관과 DPA는 운영자·최종 이용자·처리자의 역할을 나눈다. 공개 문서만으로 이번 아동 게임의 운영이 명시적으로 승인되었다고 결론 내리지 않는다. 운영자의 실제 계약에는 **한국의 개인 운영자, 만 14세 미만 포함, 보호자 동의를 받은 최소 계정정보·플레이 기록의 저장**이라는 사용 범위가 맞아야 한다. [개인정보처리방침][cf-privacy] [약관][cf-terms] [Developer Platform 약관][cf-developer] [DPA][cf-dpa]

2026-10-20 확인한 Workers Paid 기본료는 계정당 최소 **월 US$5**다. 월 Worker 요청 1천만 회와 CPU 3천만 ms가 포함되고 초과 사용량은 별도다. D1 Paid에는 월 읽기 250억 행, 쓰기 5천만 행, 저장 5GB가 포함된다. 이 금액은 총운영비나 상한액이 아니다. 도메인, 동의 확인, 이메일·문자, 세금, 선택한 부가 기능은 실제 구성에 따라 추가된다. [Workers 요금][workers-pricing] [D1 요금][d1-pricing]

D1의 `apac` 위치 힌트는 한국 저장을 보장하지 않는다. 실제 처리국가·수탁업체·국외 이전 근거와 이용자 고지 범위를 확인한 뒤 데이터 구성을 정한다. [D1 데이터 위치][d1-location]

### 이전 시 필요한 코드 작업

| 대상 | 해야 할 작업 |
|---|---|

| 로그인 UI | 독립 환경에서 Sites 로그인·로그아웃 예약 경로와 계정 전환 경로를 제거하고 자체 세션으로 연결한다. |

특히 `app/chatgpt-auth.ts`는 Sites의 인증된 앞단이 넣는 헤더를 전제로 한다. 이를 독립 공개 서버에서 그대로 사용하면 요청자가 헤더를 만들어 계정을 가장할 위험이 있다. 이전 검증에는 **위조 Sites 헤더로 로그인·기록 조회·구매가 되지 않는지**를 포함한다.

현재 저장소의 `vinext`는 고정된 베타 버전이다. 전면 재작성부터 시작할 필요는 없지만 독립 빌드와 런타임 동작은 새 환경에서 확인해야 한다.

## 4. 어린이 가입 흐름 — 구현할 설계

다음은 아직 구현되지 않은 제품 설계다. 소셜 로그인 성공이나 화면의 체크 표시만으로 보호자 동의가 완료되었다고 처리하지 않는다.

1. **로그인 전에 연령에 맞는 길을 안내한다.** 만 14세 미만 경로에서는 우선 쉬운 말로 운영자·문의 주소·보호자 연락처가 필요한 이유를 설명한다. 연령 구간 판단에 불필요한 상세 생년월일을 기본 저장하지 않는다.
2. **보호자 동의 요청을 계정 생성과 분리한다.** 동의 전에 아동으로부터 직접 받는 예외 정보는 법정대리인의 성명·연락처로 제한한다. 이 단계에서 아동의 소셜 계정 식별자·이메일·닉네임·성적을 가입 정보로 모으지 않는다.
3. **보호자가 처리 내용을 읽고 동의하도록 한다.** 어떤 정보를 왜 쓰고 언제 지우는지, 랭킹에 무엇이 보이는지, 철회·삭제 방법을 안내한다. 실제 법정대리인의 의사를 확인하는 수단을 연결한다.
4. **서버가 동의 완료를 확인한 뒤 어린이 계정을 연결한다.** 보호자와 아동은 별도 주체로 관리한다. 아동에게 제공할 로그인 방식은 제공자별 아동 계정 지원 범위까지 확인하고 연결한다.
5. **보호자가 연결된 아동의 정보 관리와 철회를 할 수 있게 한다.** 보호자·아동 관계를 다시 확인하고, 다른 가족의 기록에 접근할 수 없도록 서버에서 권한을 검사한다.

개인정보보호법 제22조의2는 만 14세 미만 아동의 처리에 법에 따른 동의가 필요한 경우 법정대리인의 동의와 확인, 어린이가 이해하기 쉬운 안내를 요구한다. 모든 처리의 법적 근거가 일률적으로 동의인 것은 아니며, 실제 수집·이용별 근거는 정책에서 정한다. [개인정보보호법 제22조의2][pipa-child]

### 보호자 확인 방법

시행령 제17조의2는 웹 동의 후 보호자 문자 통지, 휴대전화 본인확인, 서면, 동의 내용에 대한 이메일 회신, 전화 등 여러 방법을 정한다. 유료 휴대전화 인증만이 법에서 허용하는 방법이라고 설명하지 않는다. [시행령 제17조의2][pipa-decree]

정식 운영에서는 확인 결과를 서버가 검증할 수 있는 외부 서비스와 동의 화면을 연결하는 방식을 우선 비교한다. 소규모 시험에서 이메일 회신 방식을 검토할 수도 있지만, 임의 이메일로 보낸 링크의 클릭 하나를 실제 보호자 동의로 간주해서는 안 된다. 선택 시에는 **본인 여부**, **이 아동의 법정대리인 여부**, **동의한 처리 내용**을 각각 어떻게 확인·기록하는지 정한다. 성인 본인확인 성공만으로 보호자 관계가 증명되었다고 처리하지 않는다.

Google Family Link의 고지는 제3자 서비스의 개인정보 처리를 자체 적용 범위에서 구별한다. 따라서 Google 쪽 보호자 승인이 하루다섯의 동의를 대신한다고 전제하지 않는다. 카카오·네이버의 아동 계정 지원과 개발자 정책은 실제 연결 전에 별도로 확인할 항목이다. [Google 공식 고지][google-family]

### 동의 대기 정보의 삭제

표준 개인정보 보호지침 제13조의 현행 전문(2025-4호, 2025-04-11 시행)은 사전 수집한 법정대리인 정보를 동의를 받는 목적에만 쓰고, 거부하거나 의사가 확인되지 않으면 **최초 수집일부터 5일 이내** 파기하도록 정한다. [현행 지침][guideline] [공식 전문][guideline-body]

제품 기준은 거절 시 즉시 삭제, 미확인 요청은 최초 수집일부터 5일 이내 자동 삭제로 정한다. 발송 재시도나 링크 재발급이 최초 수집 시각을 바꿔 보관 기간을 연장하지 않게 한다. 방문자가 다시 접속해야만 삭제되는 구현은 쓰지 않는다. 예약 작업은 기한 전에 실행되도록 여유를 두고 실패·재시도·알림까지 연결한다. 로그·메일 발송 서비스에 복제되는 개인정보의 보관도 함께 설계한다.

| 거부·미확인 만료 | 활성 계정을 만들지 않고 대기 개인정보 삭제 |
| 동의 철회 | 동의에 의존하는 신규 처리를 중단하고 게임 세션과 공개 노출을 차단. 필요한 권리 행사 경로는 유지 |
| 탈퇴·삭제 | 게임 기록·프로필·로그인 연결·세션·공개 랭킹을 처리하고 완료 결과 안내. 별도 보존 근거가 있는 정보만 분리 관리 |

서버는 활성 동의와 계정 권한을 확인해 기록 조회·플레이·구매를 허용한다. 철회나 탈퇴 후에도 권리 행사가 필요하므로 보호자용 재확인·열람·삭제 요청 경로까지 일괄 차단하지 않는다. 프런트엔드의 `guardianReady` 표시나 전역 가입 설정만으로 이를 대체하지 않는다.

동의 기록에는 요청 식별자, 보호자–아동 연결, 동의 항목과 문구 버전, 확인 방법, 확인 시각·상태, 필요한 최소 증빙 식별자를 검토한다. 일회용 링크 원문·외부 인증 비밀값은 공개 화면이나 로그에 남기지 않는다. 중복·만료 콜백은 추가 계정이나 활성 동의를 만들지 않게 한다.

랭킹에는 게임 닉네임·캐릭터·점수 등 정한 항목만 보여 주고, 실제 이름·로그인 이메일·상세 생년월일·보호자 연락처를 노출하지 않는다. 자동 추천 닉네임 등으로 어린이가 실명을 입력할 필요를 줄이는 방향을 검토한다. 개인별 육각형 통계와 상세 기록의 공개 여부는 별도로 설계한다.

보호자의 열람·정정·삭제·처리정지·철회 경로는 가입보다 어렵지 않게 구성한다. 문의 이메일은 접수 경로로 사용할 수 있지만 요청자 확인과 실제 DB 삭제·백업 반영·처리 결과 안내까지 연결해야 한다. [개인정보보호법 제38조][pipa-rights]

현재 화면이 최근 90일을 보여 주는 것은 서버 보관 기간이 90일이라는 뜻이 아니다. 게임 기록, 동의 증빙, 문의 내용, 보안 로그, 백업의 목적·근거·기간·삭제 방법을 각각 정하고 구현한다. 만 14세가 되는 시점의 안내·동의·보호자 관리 권한 전환도 별도 항목으로 다룬다.

## 6. 게임 관련 가입 의무와 수익화

게임산업법 제12조의3에는 적용 대상 게임의 가입 시 실명·연령 확인, 본인인증과 청소년의 법정대리인 동의 등 별도 규정이 있다. 시행령 제8조의3의 제공 방식·사업자·매출 등 예외 적용은 실제 운영 조건으로 확인해야 한다. 개인 개발이라는 사실이나 무료 게임이라는 설명만으로 적용 제외를 확정하지 않는다. 계정·성적을 모으는 현재 구조는 개인정보를 수집·이용하지 않는 무료 게임이라는 전제와도 다르다. 개인정보보호법의 만 14세 미만 요건은 별도로 검토한다. [게임산업법][game-act] [시행령][game-decree]

권장 수익화 순서는 다음과 같다. 이는 아직 결제·광고를 활성화한 결정이 아니다.

1. 정식 서비스의 무료 플레이·해설·주간 랭킹과 게임 코인 캐릭터 수집을 먼저 완성한다.
2. 재방문·문제 소진·운영비를 확인한 뒤, 게임 성적에 영향을 주지 않는 외형 상품이나 후원 구성을 비교한다. 기본 토끼 외 캐릭터를 전부 무료 지급하는 방식으로 바꾸지 않는다.
3. 보상형 광고는 아동 대상 처리가 가능한 제공자·설정·고지·동의 범위를 확인한 뒤 검토한다. 제안 보상은 랭킹과 분리된 추가 연습이나 외형 수집이며, 광고 시청으로 정규 경쟁 시도를 늘리는 구성은 피한다.
4. 현금 상품은 보호자 결제·취소·환불과 운영자 등록·계약 요건을 준비한 뒤 연결한다.

## 7. 기존 기록 이전 원칙

소스 ZIP은 코드와 문서의 백업이다. 기존 Sites의 D1, 모든 회원 계정, 결제·게임 거래 내역을 담은 DB 덤프가 아니다. `/api/game/export`도 로그인한 본인의 서비스 기록 내보내기이며 전체 DB 복구 파일로 쓰지 않는다.

기존 DB에 대한 정당한 내보내기 권한과 일관된 추출 경로가 확보되어야 전체 이전을 진행할 수 있다. D1에는 SQL 내보내기·가져오기 기능이 있지만 새 계정을 만들었다고 원본 DB 접근권한이 생기는 것은 아니다. [D1 이전 문서][d1-export]

기존 기록을 계속 쓸 경우에는 계정 소유권·로그인 연결을 검증하고 주간 정산·코인 원장·구매 영수증을 함께 대조한다. 같은 이메일로 자동 병합하지 않는다. 도메인 전환 시 재로그인하고 임시 인증 흐름을 새로 시작한다. 실제 전환과 쓰기 중단 범위는 이전 자료를 검토한 후 정하며 기존 기록을 임의로 초기화하지 않는다.

## 8. 다음 진행 순서와 담당

| 순서 | 준비할 결과 | 운영자에게 필요한 결정·설정 |
|---|---|---|
| 1 | 독립 호스팅의 대상 이용자·데이터 처리 적합성, 구성과 비용 확인 | Workers+D1 후보 채택 여부, 본인 소유 운영 계정, 확정된 월 3만 원 한도에 맞춘 전체 비용 확인 |
| 2 | 운영 주소와 소셜 등록 정보 마련 | 도메인 후보·소유 여부, 운영자 명의 개발자 앱 접근 |
| 3 | 보호자 확인 방식·수집 항목·삭제 정책을 문구와 기능으로 연결 | 확인 서비스의 실제 계약 조건과 가격, 공개할 운영자 정보 |
| 4 | 독립 서버·계정 분기·보호자 관리·탈퇴·예약 삭제 구현과 검증 | 필요한 비밀값을 서비스 설정 화면에 직접 입력하거나 제한된 권한으로 연결 |
| 5 | 실제 로그인, 어린이·보호자 테스트, 문의 수신·응대, 등급·등록 절차 확인 | 테스트 참여, 수신·답변 확인, 운영 절차 확정 |
| 6 | 검증된 버전·환경·전환 범위를 제시한 뒤 정식 공개 | 공개할 구체적 버전과 범위, 실제 유료 신청이 있다면 해당 항목 확인 |

계정 비밀번호·API 비밀키를 채팅에 붙여 넣을 필요는 없다. 외부 메시지 전송, 유료 가입, 도메인 구입과 정식 배포는 이번 준비 작업에서 실행하지 않았다.

### 앞으로 통과해야 할 검증

- 동의 전 아동 OAuth·계정·점수 저장이 시작되지 않는가.
- 실제 법정대리인의 동의 여부와 아동 연결을 확인하는가.
- 거부·만료·재발급·중복 콜백·동시 철회가 계정을 잘못 활성화하지 않는가.
- 대기 정보가 최초 수집 기한 안에 삭제되고, 예약 작업 실패가 감지되는가.
- 한 보호자가 다른 보호자의 아동 기록에 접근할 수 없는가.
- 철회·탈퇴 후 세션·공개 랭킹·로그인 연결·게임 데이터와 백업 처리 방침이 일치하는가.
- 실제 소셜 로그인 취소·재시도·계정 연결이 정상 작동하는가.
- 독립 서버가 위조한 Sites 인증 헤더를 신뢰하지 않는가.
- 주간 정산·문제 시간·아이템 구매가 재시도와 전환 중에도 중복 반영되지 않는가.
- 실제 모바일 화면·메일 수신·문의 답변·백업 복구·운영 도메인을 확인했는가.

위 목록은 계획이며 통과 결과로 보고하지 않는다.
