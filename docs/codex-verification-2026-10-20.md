## 1단계 변경 기록

1. Node 요구 버전을 22.16.0 이상인 22.x 또는 24 이상으로 package/lockfile/README에 일치시키고 설치·빌드·로컬 실행 전에 검사한다. Node 24 선택용 `.nvmrc`를 추가했다. 의존성 패키지 버전은 그대로다.
2. 독립용 HTTP 어댑터를 추가했다. 플랫폼 인증 헤더와 Sites 예약 경로를 사용하지 않고 자체 세션만 검증한다. 가입 설정을 잘못 켜도 이 어댑터는 신규 가입을 닫는다. 기존 Sites API와 빌드 경로를 보존했다.
3. 로그인 상태에 플랫폼 기능 여부를 포함하고 독립/미확인 환경에서는 ChatGPT 로그인 버튼을 숨긴다. 기존 카카오·Google·네이버 준비 상태와 도트 화면은 유지했다.
4. 실제 SQLite 기반 D1 시험 어댑터를 로컬 DB와 테스트가 공유한다. 영속 DB의 마이그레이션 해시·중복 적용·실패 롤백을 추가했다. 데이터는 `.local/`에 보관하며 Git에서 제외한다.
5. 로컬 127.0.0.1 미리보기는 공개 게임 자산만 제공하며 비밀값·문제은행·DB 파일 경로는 제공하지 않는다. 사용자·쿠키·실제 로그인 성공을 자동 생성하지 않는다.
6. 보호자 동의·철회·삭제·예약 작업의 다음 구현 계약과 경쟁 조건 검증 목록을 문서화했다. 해당 기능의 서버·외부 확인·예약 실행을 완료한 것은 아니다.

## 후속 단계: 보호자 동의·철회·삭제 서버

`0004_guardian_privacy.sql`로 5개 테이블을 추가하고 보호자 증빙·계정 허가·가족 관계·삭제 요청을 원자적으로 처리한다. 기존 마이그레이션 0000~0003을 수정하지 않았다. 실제 원격 또는 로컬 개발 DB를 정리·삭제하지 않고 격리된 테스트 DB에서 검증했다.

추가 검증은 서명된 JWT의 잘못된 주체·관계·항목·문구 버전, 재사용·만료, 고정 요청 기한, 철회와 답안·구매·프로필·순위 집계의 경쟁, OAuth 중 철회, 다른 가족 접근, SQL 실패 롤백, 명시적 정책 없는 삭제 대기와 정책을 전달한 DB 삭제, 로그아웃 후 민감한 요청 거부를 다룬다.

자체 보안 검토에서 민감한 API의 최초 세션 검사만으로 로그아웃 후 늦은 처리를 막지 못하는 문제를 재현했다. 최종 SQL 세션 검사와 자기 세션 철회 순서를 보완하고 회귀 테스트를 추가했다. 실제 외부 제공자 증빙이나 운영 계정으로 확인한 결과는 아니다.

## 후속 단계: 보호자 안내·정보 관리 화면

로그인 전에도 볼 수 있는 `#guardian` 안내와 `#privacy` 정보 관리 화면을 추가했다. 실제 보호자 확인이나 어린이 가입을 받는 입력 화면은 아니다. 기존 인증 계정에는 최근 로그인 상태 및 공개 플레이어 ID를 확인한 뒤 본인 기록 내보내기와 서버가 확인한 어린이 목록·철회·삭제 요청 UI를 제공한다. 본인 탈퇴·삭제는 후속 재인증 경로가 없어 비활성 상태로 유지했다.

화면은 계정·메뉴 변경, 로그아웃, 숨김·복원, 컨트롤러 종료 시 이전 응답과 확인 상태를 폐기한다. 다운로드 전에도 현재 계정 문맥과 대상 연결을 다시 확인한다. 삭제 접수와 완료를 구별하며 응답이 불확실한 쓰기는 자동 재전송하지 않는다. 확인 창의 취소 버튼뿐 아니라 Esc·바깥 클릭도 요청 허가를 지운다.

검토 중 상태 조회 직후 다른 계정으로 쿠키가 바뀌면 다른 가족 목록이 이전 화면에 표시될 수 있는 경합을 발견했다. 최초 상태 조회를 제외한 개인정보·보호자 GET 목록에도 `X-Haru-Account`를 요구하고, 다른 계정 및 같은 계정의 새 세션을 409로 거부하도록 수정했다. 해당 거부 시 목록 SQL과 할당량 변경도 실행하지 않는 것을 실제 SQLite 검사로 확인했다. 보호자 요청 거부는 작업 토큰으로 두 삭제를 함께 처리해 세션 기한 경계에서 증빙만 사라지는 부분 처리를 막았다.

로그인 뒤 정보 관리 화면의 동작은 테스트 fixture 검증이다. 실제 이용자·가족 계정으로 제공자 왕복을 진행하거나 휴대폰 실기기로 확인한 결과가 아니다. 독립 개인정보 API는 로컬 독립 어댑터에 연결되며 기존 Sites 빌드 성공을 독립 운영 배포 성공으로 간주하지 않는다. 실제 성인/아동 가입·보호자 본인 및 관계 확인·대상 아동 연결·본인 재인증·운영 예약 삭제·보존/백업 정책은 계속 미완료다. `HARU_REGISTRATION_OPEN=false`, `loginEnabled:false`, `guardianReady:false`, `selfRecoveryReady:false`를 유지한다.
