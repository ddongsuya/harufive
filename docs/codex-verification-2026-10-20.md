## 후속 단계: 보호자 동의·철회·삭제 서버

## 후속 단계: 보호자 안내·정보 관리 화면

로그인 전에도 볼 수 있는 `#guardian` 안내와 `#privacy` 정보 관리 화면을 추가했다. 실제 보호자 확인이나 어린이 가입을 받는 입력 화면은 아니다. 기존 인증 계정에는 최근 로그인 상태 및 공개 플레이어 ID를 확인한 뒤 본인 기록 내보내기와 서버가 확인한 어린이 목록·철회·삭제 요청 UI를 제공한다. 본인 탈퇴·삭제는 후속 재인증 경로가 없어 비활성 상태로 유지했다.

화면은 계정·메뉴 변경, 로그아웃, 숨김·복원, 컨트롤러 종료 시 이전 응답과 확인 상태를 폐기한다. 다운로드 전에도 현재 계정 문맥과 대상 연결을 다시 확인한다. 삭제 접수와 완료를 구별하며 응답이 불확실한 쓰기는 자동 재전송하지 않는다. 확인 창의 취소 버튼뿐 아니라 Esc·바깥 클릭도 요청 허가를 지운다.

검토 중 상태 조회 직후 다른 계정으로 쿠키가 바뀌면 다른 가족 목록이 이전 화면에 표시될 수 있는 경합을 발견했다. 최초 상태 조회를 제외한 개인정보·보호자 GET 목록에도 `X-Haru-Account`를 요구하고, 다른 계정 및 같은 계정의 새 세션을 409로 거부하도록 수정했다. 해당 거부 시 목록 SQL과 할당량 변경도 실행하지 않는 것을 실제 SQLite 검사로 확인했다. 보호자 요청 거부는 작업 토큰으로 두 삭제를 함께 처리해 세션 기한 경계에서 증빙만 사라지는 부분 처리를 막았다.

## 후속 단계: 기존 활성 계정의 최근 본인 확인

최근 인증 기준을 세션 생성 시각에서 검증한 ID 토큰의 `auth_time`으로 분리했다. 새 `0005_recent_reauthentication.sql`은 기존 세션과 OAuth 요청을 보존하며 `authenticated_at`, 재인증용 원래 세션·연결 신원 문맥을 추가한다. 기존 세션의 인증 증거는 NULL이고 `iat`나 세션 생성 시각으로 채우지 않는다. 이전 0000~0004 마이그레이션은 보존했다.

재인증은 이미 활성 상태인 계정과 유효한 자체 세션에서만 시작한다. 최근 인증 여부와 별개로 현재 세션의 문맥을 확인하고, 원래 계정·세션·연결 제공자를 고정한다. 서명·issuer·audience·nonce·PKCE와 실제 최근 `auth_time`을 검증한 뒤 DB 처리 시점의 활성 계정·원래 세션·연결 신원을 다시 비교하여 세션 교체와 이전 세션 폐기·요청 소비를 원자적으로 처리한다. 새 계정이나 로그인 연결을 만들지 않는다.

정보 관리의 **최근 본인 확인**은 재인증 시작 직전 상태를 다시 조회한다. 취소·화면 이동·탭 숨김·로그아웃·계정 전환·컨트롤러 종료 뒤 도착한 URL을 사용하지 않는다. 콜백 표시 자체로 권한을 인정하지 않고 정보 관리 API를 다시 조회하며 과거 철회·삭제 요청을 자동 실행하지 않는다.

중간 검토에서 인증 요청의 리디렉션 거부 누락과 취소 후 재시도 문제를 수정했다. 클라이언트 URL 검사와 서버의 제공자별 재인증 파라미터가 어긋나는 문제도 수정했다. Google은 `max_age=0`, Kakao는 이에 `prompt=login`, Naver는 이에 `auth_type=reauthenticate`를 추가하는 준비 계약으로 일치시켰다. 잘못된 제공자 조합·중복·누락 파라미터를 거부한다. 이것은 실제 제공자의 지원을 확인한 결과가 아니다. 중간 개별 테스트 실패를 통과로 계산하지 않았고 최종 전체 검사와 빌드는 모두 통과했다.

**남은 연결 조건:** 실제 제공자별 로그인 화면 강제·서명된 `auth_time` 발행을 확인해야 한다. Google의 `max_age`, Kakao 환경별 로그인 제약, Naver의 현재 OIDC 경로 지원을 실계정으로 검증하지 않았다. `auth_time`을 받지 못하면 민감한 권한은 계속 거부한다. 새 로그인·가입, 실제 보호자 확인·아동 연결, 폐쇄 계정 권리 행사·복구, 운영 보관/백업 정책·예약 실행은 미완료다. `HARU_REGISTRATION_OPEN=false`, `loginEnabled:false`, `reauthEnabled:false`, `guardianReady:false`, `selfRecoveryReady:false`와 본인 탈퇴·삭제 비활성을 유지한다.

로그인 후 새 화면은 fixture로 확인했고 실제 로그인한 브라우저·휴대폰·제공자 왕복을 검증한 것은 아니다. 기존 Sites 빌드 성공을 독립 운영 배포로 보지 않는다. 사용자는 도메인·서버·인증을 포함한 월 운영 예산을 **3만 원 이내**로 확정했으며, 호스팅·도메인·인증 계약과 배포는 진행하지 않았다.


## 후속 단계: 독립 Worker 로컬 검증과 운영 비용 조사

별도 `server/worker.mjs`와 `wrangler.standalone.jsonc`로 기존 독립 어댑터를 Worker에 연결했다. 기존 Sites의 프로젝트·빌드·배포 설정은 보존했다. 새 설정은 로컬 시험 D1, 원격 바인딩 비활성, workers.dev·preview URL 비활성, 운영 원점 없는 경우 loopback만 허용하도록 고정한다. 임의 비밀 환경값이나 플랫폼 인증 정보는 서비스에 전달하지 않는다.

공개 파일 14개를 명시 목록으로만 준비하고 알 수 없는 파일·링크가 생성 폴더에 있으면 삭제 없이 실패한다. Worker가 모든 요청을 먼저 확인해 API·허용 자산·미등록 경로를 분리한다. 원점·메서드·비공개 경로와 응답 보안 헤더를 검사하며 SPA fallback을 사용하지 않는다. 기존 게임 규칙·계정·가입 준비 상태는 바꾸지 않았다.

로컬 runner는 네 모드만 받으며 추가 인수·원격 모드를 거부한다. 준비용 build gate는 실수 방지 검사이고, 소스나 CLI를 변경할 권한이 있는 사용자의 수동 실행을 막는 보안 장치로 표현하지 않는다. 빈 env 파일을 명시하고 부모 인증키·Cloudflare 토큰·NODE_OPTIONS를 자식 프로세스에 전달하지 않는 경계를 설치된 Wrangler 코드와 대조했다.

## 후속 단계: 만 14세 이상 가입·이용으로 전환

사용자가 어린이 포함 B안을 철회하고 만 14세 이상만 가입·이용 대상으로 정했다. 현재 기준은 `docs/age-eligibility.md`이며 앞선 절의 어린이 포함 결정·구현·검증은 당시 이력이다. 실제 이용자의 나이, 기존 계정·동의 기록과 가족 관계를 추정해 변경하거나 삭제하지 않았다.

`server/admission-policy.mjs`는 최소 가입 연령 14, 공개 가입 닫힘, 어린이 신규 가입 닫힘, 실제 연령 확인 미준비를 명시한다. 인증 및 개인정보 상태 응답에 정책을 포함한다. 기존 환경 변수 `HARU_REGISTRATION_OPEN=true`만으로 소셜/일반 Sites 신규 계정을 생성하던 분기를 차단했다. 서명된 소셜 신원이 있어도 아직 설계·검증하지 않은 연령 claim을 가입 증거로 사용하지 않는다. 기존 연결 신원의 로그인·명시된 개발용 Sites 테스터는 보존하되 이를 연령 확인 완료로 보지 않는다.
