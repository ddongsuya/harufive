# 2026-10-21 시험 사이트 연결 기록

## 비밀번호 8~16자 및 Windows 배포 실행 환경 수정

사용자는 배포 단계의 종료 코드 3221226505를 보고했다. 로컬 결과 파일에서 계정 확인·DB 사전 확인·마이그레이션·적용 후 7개 이력 재확인은 정상 종료했고, 배포만 실패 종료했다. 사용자 제공 출력에 `Worker Startup Time: 8 ms`와 DB/DO binding이 있었으며 이후 실제 사이트의 회원가입 탭이 보인다고 확인했다. 새 코드 일부 반영과 화면 확인 증거이며 최종 배포 명령 완료·실제 가입·게임 저장 증거와는 구별한다.

가입 입력 단계에서 사용자가 비밀번호를 **8~16자**로 변경해 달라고 요청했다. 신규 가입의 입력란·확인란·오류 문구·클라이언트 검사·서버 검사·DO 해시 생성에 함께 적용했다. 기존 계정의 17~128자 비밀번호 검증과 로그인은 보존한다. scrypt 비용·형식, 공백 보존, 세션·CSRF·요청 제한·DB 구조는 바꾸지 않았다.

Windows 실행 환경은 기존 Node 24.13.0에서 별도 폴더의 공식 **24.22.0**으로 교체했다. Node 24.20.0에 포함된 Windows libuv assertion 수정 #61999를 포함한다. Node 실행 파일 SHA-256 `ba93f9a70bd86fce3ebbb39ec758501458453467aa92a34a0a3602d1e3fc2b9c`가 공식 SHASUMS와 같고 Authenticode 서명 OpenJS Foundation의 유효 상태를 확인했다. 시스템 설치·사용자 PATH·Wrangler 버전·의존성 lockfile은 변경하지 않았다. 생성한 CMD는 준비에 사용한 실행 파일의 절대 경로와 종료 코드를 보존하고, 결과 파일에는 Node 버전을 추가한다. 비정상 종료를 성공으로 취급하지 않는다. 실제 사용자 충돌의 정확한 내부 원인은 확인하지 못했다.

- Node 24.22.0 전체 **614개 테스트 통과**, 실패·취소·건너뜀 0. 구문·타입 검사 및 변경 공백 검사 통과.
- 서버·해시 관련 95개, UI 관련 32개, 배포 실행 파일 관련 22개 개별 검사도 통과했다. 7/17자 가입 거절, 8/16자 허용, 기존 긴 비밀번호 로그인·검증, 비정상 배포 종료 시 완료 표시 금지를 포함한다.
- 가입용 Worker 오프라인 dry-run 및 실제 로컬 workerd·D1·SQLite DO **12개 시나리오 통과**. 7/17자 서버 거절, 16자 공백 포함 비밀번호 가입, 문제 저장, 로그아웃·재로그인 후 기록 복원, 합성 서명 Google 가입을 확인했다. 외부 네트워크 0회, 로컬 런타임 종료 확인.
- 최초 전체 검사는 별도 dry-run과 동시에 공유 번들을 갱신해 Windows 파일 잠금으로 1개 실패했다. 동시 빌드를 끝낸 뒤 전체 검사만 다시 실행하여 위 614개를 통과했다. 제품 동작 실패로 숨기거나 테스트를 건너뛰지 않았다.

새 조건 번들 SHA-256: `e8081f5b57d21a3852079f64e31cc288ab10325151a2d2a3702e35ff6f543ba9`, gzip 167816바이트. 이번 수정의 원격 배포·실제 회원가입·Google 왕복·원격 게임 저장은 미확인이다. 추가 DB 마이그레이션은 없다.

## 로그인 이후 배포 실행 중단 수정

사용자는 원격 회원가입 탭과 `localAuth` 항목이 없고, 배포 창에 `Successfully logged in.` 다음 일반 오류가 표시됐다고 보고했다. 이전 실행 파일은 모든 비정상 종료를 같은 문구로 처리했다. 설치된 Wrangler 4.92 소스는 자격 증명 저장·성공 문구 이후에도 캐시 정리 등에서 실패할 수 있지만 사용자 종료 코드를 관찰하지 못했으므로 특정 원인을 확정하지 않는다.

배포 실행 파일에 `whoami --json`을 통한 대상 계정 확인을 추가했다. 기존 로그인이 유효하면 로그인 단계를 생략한다. 로그인 명령이 실패 종료하더라도 별도 확인 명령이 정상 종료하고 대상 계정을 반환해야만 이어간다. 사용자 취소, 확인 실패·이상 응답·다른 계정, DB 이력 실패는 배포를 막는다. 기존 DB의 정확한 6/7개 이력 확인과 적용 후 7개 재확인은 유지한다. 자식 프로세스의 출력 수신이 끝난 `close`에서 응답을 파싱하며 단계·종료 코드를 표시한다.

- `node --test tests/signup-deployment-package.test.mjs`: **20개 통과**, 실패·취소·건너뜀 0. 합성 CLI만 사용했으며 원격 요청은 없다.
- 기존 로그인 재사용, 성공 문구 뒤 exit1과 실제 계정 확인 성공/실패, 미로그인 JSON의 exit1, 다른 계정·잘못된 JSON·실패 코드, Windows 포함 취소 코드, DB 전후 이력 확인 실패, 마이그레이션 거절 후 배포 차단을 검증했다.
- `deployment-result.json`은 고정 단계·종료 코드·확인/완료 여부만 저장한다. 합성 비밀값·이메일·원문 출력 제외 및 실행 초기에 이전 성공 결과를 미완료로 바꾸는 동작을 검사했다.
- 준비 스크립트·생성 실행 파일·테스트의 구문 검사 및 변경 공백 검사 통과. 게임 소스·Worker 번들은 변경하지 않았다. 번들 SHA-256은 아래 기존 검증과 동일하다.

현재 개발 PC의 배포 폴더와 ZIP을 갱신했다. 에이전트는 이 실행 파일이나 원격 명령을 실행하지 않았다. 사용자 재실행, 회원가입 화면 표시, 실제 원격 가입·기록 보존·Google 로그인은 확인 전이다. 아래 587개 전체 검사는 가입 기능 구현 시점의 결과이며 이번 실행 도구 수정에서는 관련 20개만 재검증했다.

- 원격 관리자·시험 원점 접근 차단은 유지한다. 이 후속 결과는 사용자 보고·스크린샷에 근거하며 다른 도구로 원격을 관찰하거나 SQL을 실행한 결과가 아니다. 신규 가입·첫 운영자 계정·실제 제공자 왕복·게임 저장·재접속은 미완료다.

## 이번 로컬 수정 — 원격 적용과 구별

시험 입장 후 앱 세션 401이 브라우저의 HTTP Basic 자격 증명 재요청과 충돌할 수 있는 경로를 수정했다. 미리보기 내부 앱 401만 HTTP 403과 `X-Haru-Application-Status: 401`로 전달하고 게임·인증·정보 관리 클라이언트는 기존 세션 만료 처리를 유지한다. 입장 비밀번호 실패의 401 challenge와 실제 403 권한 거절은 그대로다.

연결용 모드에 고정 원점·비밀번호 인증 뒤만 사용할 수 있는 `GET /api/preview/config`를 추가했다. 제공자 설정의 `missing`·`not_text`·`empty`·`too_long`·`invalid_characters`·`present` 분류만 반환하며 비밀값·길이·해시는 반환하지 않는다. `present`는 구문 조건 통과이며 제공자의 인증 성공은 아니다. 첫 서버 snapshot의 날짜가 기기 날짜와 다를 때 요청한 화면 경로를 잃던 분기도 수정했다.

이 단락은 코드 변경 기록이다. 이번 수정의 검증 결과와 새 번들의 원격 배포 완료를 기존 DB 준비 확인이나 과거 검사 수치로 대신하지 않는다.

## 실제 시험 사이트

사용자가 `harufive-preview` Worker를 생성하고 보호된 정적 번들을 Edit code에서 Deploy했다. 번들은 627,703바이트, SHA-256 `91be61eb0aa34f579934946cf1e14e918a6306671cd459e992ce03d9dffd8f46`다.

시험 주소는 `https://harufive-preview.limjm900202.workers.dev`다. 사이트 관찰 도구의 권한 차단이 발생하기 전에 자격 증명 없는 HTTP 요청으로 다음을 확인했다.

- 최초 기본 예제: 200 Hello World.
- 보호 코드 적용·secret 미설정: `/`, `/game/app.js`, `/api/health`, `/api/auth/status`, `/.env`가 503 `PREVIEW_NOT_CONFIGURED`; no-store/private/noindex 확인.
- 사용자 secret 저장 후: `/`, `/game/app.js`, `/api/auth/status`가 401 `PREVIEW_AUTH_REQUIRED`; Basic challenge와 no-store/private 확인. 사용자 UI에는 저장 뒤 별도 Deploy 버튼이 없었으며 401 변화로 저장 적용을 확인했다.

그 후 브라우저 도구가 해당 시험 원점의 관찰을 URL 보안 정책으로 거부했다. 다른 브라우저·HTTP·CLI로 우회 관찰하지 않았다. Cloudflare 관리 화면도 기존 저장된 사이트 권한 차단이 유지되어 사용자가 직접 작업했다.

내장 브라우저의 `ERR_INVALID_AUTH_CREDENTIALS` 이후 사용자가 일반 브라우저에서 직접 사용자명·비밀번호를 입력했고, 하루다섯의 “기록 저장소를 준비하고 있어요” 화면을 스크린샷으로 제공했다. **사용자 보고·스크린샷 기준 시험 입장과 화면 렌더링은 성공**했으며, 이는 소셜 로그인·게임 기록 저장 성공은 아니다. 배포한 정적 번들은 DB를 전달하지 않아 해당 안내가 예상된다.

실제 비밀번호를 받거나 읽지 않았다. PC의 5181 포트 도구는 사용자 클릭으로 브라우저에서 비밀번호를 만들고 복사하도록 준비했으며 생성 후 화면·DOM·클립보드를 관찰하지 않는다. 사용자 비밀 보관을 확인하기 전 도구를 임의로 닫지 않는다.

## D1 준비

사용자가 `harufive-preview-db` 생성·초기화·Worker DB 바인딩·연결 번들 교체를 완료했다고 알렸다. 관리 콘솔 관찰이나 원격 SQL 실행은 하지 않았다. 후속 `/api/health` 사용자 스크린샷으로 서버·DB 준비를 확인했으며 위 최신 상태를 우선한다.

`scripts/preview-db-schema.mjs`는 최종 스키마만 생성하는 새 빈 DB 전용 파일, 정확한 구조·빈 표 확인 후 적용 이력을 기록하는 파일, 읽기 전용 확인 파일을 준비한다. 운영 계정·게임 데이터·비밀값을 포함하지 않는다. [수동 연결 안내](preview-database-setup.md)를 따른다.

### DB 초기화 도구의 로컬 검사 결과

- 새 검사 **4개 통과**, 실패·취소·건너뜀 0. 마이그레이션과 최종 SQL 정의 일치, D1 내부 표 보존, 기존 자료·누락 인덱스·알 수 없는 추가 표의 이력 기록 거절, 반복 실행 시 자료 보존을 확인했다.
- 실제 새 로컬 D1에서 합본 **46개 SQL 성공**, `HARUFIVE_SCHEMA_READY`, 앱 표 **18개**, 이력 **6개**, 저장 자료 **0개**, 외래 키 위반 **0개**.
- 설치된 Wrangler 4.92.0의 로컬 migrations list에서 **No migrations to apply**. 기존 로컬·원격 DB에는 실행하지 않았다.
- 처음 검사에서 D1 내부 `_cf_METADATA`가 추가 표로 분류되어 이력 기록이 거절됐다. 이 내부 표만 명시적으로 제외한 뒤 새 격리 DB에서 재검증했다. SQL 정의 비교나 앱 데이터 비어 있음 조건을 완화하지 않았다.
- 합본 `setup-database.sql`: **29,283바이트**, SHA-256 `3cca7e566c9a952403e2ba45b05a30eba787f4f88d92cc55d6f6e9fc855bd595`.

이 DB 초기화 도구 단계에서는 앱 런타임을 변경하지 않아 기존 앱 전체 검사·빌드를 다시 실행하지 않았다. 신규 도구의 구문 검사와 위 데이터베이스 검증을 수행했다. 이후 사용자가 새 원격 D1의 Console에 초기화 SQL을 직접 적용했고 표 19개·이력 6개를 보고했다. 이 로컬 검사 수치를 후속 앱 수정의 검사 결과로 재사용하지 않는다.

## 남은 확인

- 검증한 수정 번들의 원격 반영, Google `not_configured`의 원인 진단. 이미 준비된 DB는 다시 초기화하지 않는다.
- JS 붙여넣기와 별개인 원격 preview URL·runtime·CPU 설정 대조. Logs OFF는 사용자 보고로 완료됐다.
- Google 설정 수신·콜백 및 카카오·네이버 설정, 첫 운영자 계정의 가입 허가와 실제 로그인 왕복·저장·재접속.
- 백업·복원·삭제와 권리 행사, 실제 기기, 가입 정책·공개 조건·광고 연결.

일반 가입은 닫혀 있다. 카드 등록·Zero Trust 활성화·유료 전환·PR 병합은 하지 않았다. 기존 전체 396개 테스트·앱 빌드·실제 로컬 Worker 검증은 [전날 기록](codex-verification-2026-10-20.md)이며 실제 원격 게임 성공으로 간주하지 않는다.
