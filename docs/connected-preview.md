# 기존 계정용 로그인·게임 저장 연결 준비

**최신 안내:** 현재 적용 대상은 [아이디·Google 가입용 시험본](signup-preview.md)입니다. 사용자가 직접 가입으로 범위를 바꿨으며, 이 문서의 운영자 한 명·코드만 교체·추가 마이그레이션 없음은 이전 구성 설명입니다. 새 시험본은 0006 마이그레이션과 비밀번호 처리기 namespace를 함께 배포합니다.

2026-10-21 최신 상태. **연결용 시험본은 사용자 배포 보고와 `/api/health` 스크린샷의 `status:ok`, `database:ready`까지 확인했다.** D1 초기화 결과 19개 표·이력 6개, `DB` 바인딩과 Logs OFF도 사용자 보고로 완료됐다. 이후 사용자가 보호된 설정 진단의 Google `clientId`·`clientSecret` 모두 `present`를 알렸고 Google 버튼 이용 뒤 신규 가입이 닫힌 화면을 보냈다. 설정 진단과 실제 첫 게임 계정·저장 성공은 구별한다.

사용자가 Google 계정 한 개를 운영자 시험 가입 대상으로 명시적으로 확인해, 현재 별도 [운영자 전용 시험본](owner-preview.md)을 준비했다. `server/owner-preview-worker.mjs`의 빌드 정책에 고정한 Gmail·`notBefore`와 실제 검증된 새 Google 로그인, 빈 계정 DB 조건으로 시험 계정 한 개만 생성한다. **이 문서의 기본 연결용 시험본은 기존 계정 전용으로 유지하며 일반 가입과 연령 확인을 열지 않는다.** 새 시험본의 원격 배포·본인 게임 로그인·기록 저장은 아직 미확인이다. 기존 `worker.js` 교체만 필요하며 DB·비밀 설정 유지, 추가 마이그레이션 없음이 적용 원칙이다. 아래 이전 진행 순서의 `not_configured`와 첫 가입 미준비 설명은 당시 기록이다.

## 두 구성

| 항목 | 정적 시험본 | 연결용 시험본 |
|---|---|---|
| 준비 명령 | `npm run build:preview` | `npm run build:connected-preview` |
| 오프라인 검사 | `npm run check:preview` | `npm run check:connected-preview` |
| 출력 | `.local/private-preview/worker.mjs` | `.local/connected-preview/worker.mjs` |
| 제공 범위 | 안내 화면 | 연결된 기존 계정의 소셜 로그인·게임 기록 저장 코드 |
| DB·제공자 설정 | 전달하지 않음 | 시험 비밀번호 인증 뒤 DB와 허용한 7개 OAuth 설정만 전달 |
| 새 일반 가입·강제 재인증 | 닫힘 | 닫힘 |

명령은 파일 준비와 오프라인 dry-run만 수행한다. 추가 원격 인수를 거절하며 실제 계정 인증·원격 배포·DB 마이그레이션을 하지 않는다. `wrangler.connected-preview.jsonc`의 DB ID는 0으로 된 **로컬 검사 전용 placeholder**이고 `remote:false`다. 이 설정을 실제 원격 DB 설정으로 사용하지 않는다.

두 번들은 허용된 정적 자산 15개만 포함한다. 비밀번호는 번들에 포함하지 않으며 고정 HTTPS 원점과 HTTP Basic 인증을 모든 경로 앞에서 확인한다. 연결용 entry의 DB·제공자 설정은 getter로 지연해 원점·비밀번호 검사 전에 접근하지 않는다. 관련 설정 이름은 `server/worker.mjs`의 명시적 허용목록이며 환경 전체·Sites 신원·보호자 확인키·가입 허용 플래그는 넘기지 않는다.

## 이번 로컬 연결 문제 수정

시험 입장 비밀번호와 게임 계정의 세션은 서로 다르다. 앱 세션이 없거나 만료되어 하위 API가 401을 반환하면 브라우저의 HTTP Basic 인증 재요청과 충돌할 수 있어, 미리보기 경계에서만 해당 응답을 HTTP 403과 `X-Haru-Application-Status: 401`로 전달한다. 공개 클라이언트의 게임·인증·정보 관리 전송기는 이를 기존 앱 401로 해석한다. 비밀번호 누락·불일치는 기존 HTTP 401 challenge를 유지하며 실제 권한 거절 403은 변경하지 않는다.

연결용 모드의 `GET /api/preview/config`는 고정 원점·시험 비밀번호 검사 뒤에만 세 제공자의 client ID·secret 상태를 반환한다. 값·길이·해시를 내보내지 않으며 `missing`, `not_text`, `empty`, `too_long`, `invalid_characters`, `present` 중 하나로 분류한다. `present`는 형식 검사 통과만 뜻하며 실제 제공자 인증 성공은 아니다. GET 외 메서드는 거절하고 정적 모드에는 진단을 열지 않는다. 기존 가입·재인증 경계는 그대로 유지한다.

첫 서버 snapshot의 날짜가 기기 날짜와 달라도 요청한 화면 경로를 보존하도록 첫 초기화와 기존 계정의 날짜 변경을 구분했다. 이 로컬 수정의 검사 결과와 원격 반영 여부는 [최신 검증 기록](codex-verification-2026-10-21.md)을 따른다.

## 기존 계정의 의미

연결 모드도 빈 DB에 가입자를 만들지 않는다. `auth_accounts`와 `auth_identities`의 provider·issuer·audience·subject가 검증한 소셜 토큰과 일치하는 기존 계정만 이어 사용한다. 이메일이 같거나 같은 운영자가 관리한다는 이유로 계정을 자동으로 만들거나 합치지 않는다.

다른 앱에서 새 개발자 앱으로 바뀌면 audience와 제공자별 subject도 달라질 수 있다. 기존 Sites 계정을 새 소셜 계정에 임의로 연결하지 않는다. 실제 첫 운영자·일반 가입은 연령·가입 허가 정책과 확인 방법, 이를 계정 생성에 연결하는 별도 절차가 필요하다.

실제 서명된 `auth_time`이 없는 로그인은 최근 본인 확인으로 취급하지 않는다. 강제 재인증과 자기 탈퇴·폐쇄 계정의 후속 권리 경로는 계속 닫혀 있다. 기존 확인된 가족 권리는 보존한다.

## 검증 경계

서명된 테스트 토큰·제공자 응답 fixture·격리 SQLite를 사용해 세 제공자의 기존 계정 로그인, 게임 시작·중복 요청·답안 저장·로그아웃·새 로그인 뒤 진행 복원을 검사한다. 비밀번호 실패·다른 원점·잘못된 상태/서명·만료·재사용·알 수 없는 신원·철회 계정을 차단하고 비밀번호·인증 쿠키를 제공자에게 넘기지 않는다.

이는 실제 제공자의 심사·로그인 화면·발급 토큰·원격 D1 성능을 증명하지 않는다. 검사 수와 실제 결과는 [검증 기록](codex-verification-2026-10-20.md)에 남긴다.

## 실제 연결 순서

1. **완료:** 사용자가 `harufive-preview`를 생성하고 정적 보호 코드를 배포했다. 관리 콘솔 접근 제한을 다른 도구로 우회하지 않았다.
2. **완료:** 운영자가 `HARU_PREVIEW_PASSWORD`를 직접 저장했다. 도구 접근이 허용됐을 때 익명 요청 503→401을 확인했고, 이후 사용자 스크린샷으로 비밀번호 입장·정적 화면을 확인했다.
3. **사용자 보고·스크린샷 확인:** `harufive-preview-db`의 초기화·`DB` 바인딩·연결 코드 적용 뒤 `/api/health`가 서버·DB 준비 상태를 반환했다. [DB 연결 안내](preview-database-setup.md)의 초기화를 다시 실행하지 않는다. 백업·복원 및 삭제 경계는 별도 검증이 필요하다.
4. **진행 중:** Google 두 설정을 Production의 Secret으로 등록했다고 사용자가 확인했으나 서버는 `not_configured`를 반환했다. 위 로컬 수정의 검증·반영 뒤 비밀값을 읽지 않는 진단으로 원인을 좁히고 실제 원점과 개발자 앱 복귀 주소를 대조한다. 채팅 입력 오타를 실제 설정명 오류로 단정하지 않는다. 카카오·네이버 설정은 아직 미완료다.
5. 권한과 출처가 확인된 기존 신원 연결 또는 별도로 검증한 첫 가입 절차를 준비한 뒤 실제 로그인·게임 저장·재접속을 검증한다. 빈 DB에 임의 계정을 넣어 성공으로 표시하지 않는다.
6. 정책·연령/가입 허가·본인 권리 행사·모바일·광고 조건을 완료하기 전 일반 공개 가입은 열지 않는다.
