# 로컬 개발과 독립 서버·Worker 준비

## 실행

`package.json`이 있는 게임 폴더에서 실행한다. Node 22.16.0 이상인 22.x 또는 Node 24 이상이 필요하며 Node 24를 권장한다. 23.x는 지원 대상으로 선언하지 않는다. 검증한 현재 PC는 Windows + Node 24.13.0 / npm 11.10.0이다.

```sh
npm run install:ci
npm run check
npm test
npm run build
npm run db:local
npm run dev:local
```

마지막 명령은 `http://127.0.0.1:5174`에서 현재 게임의 공개 화면과 API를 실행한다. 같은 컴퓨터에서 접속한다. 종료는 실행한 창에서 Ctrl+C다. 포트가 사용 중이면 `HARU_LOCAL_PORT`를 지정할 수 있다. 서버 바인딩은 항상 127.0.0.1이고 Host도 실제 포트와 일치해야 한다.

`npm run dev`·`npm run build`·`npm start`는 기존 Sites/Vinext 경로로 남아 있다. `dev:local`은 현재 공개 JS·CSS·도트 자산과 동일한 게임/인증 서비스를 재사용하는 별도 Node 미리보기다. React/Vinext의 렌더링, Cloudflare Workers의 실행 제한, 실제 D1 성능까지 대체하는 환경은 아니다.

## 로컬 Worker로 확인하기

별도 Worker 진입점과 공개 파일 준비 구성을 로컬에서 실행할 수 있다. 아래 명령은 실제 업로드·운영 DB 연결을 하지 않는다. 이미 설치한 프로젝트 루트에서 순서대로 실행한다.

```sh
npm run build:worker
npm run db:worker
npm run dev:worker
```

| 명령 | 실행 범위 |
|---|---|
| `build:worker` | 고정 공개 자산 14개를 준비하고 Wrangler `deploy --dry-run`으로 번들을 검사. 실제 업로드 없음 |
| `db:worker` | `--local`로 0000~0005 마이그레이션을 적용. 기존 적용 이력은 유지 |
| `dev:worker` | `http://127.0.0.1:8787`의 로컬 Worker 실행. 종료는 Ctrl+C |

Node 미리보기의 5174와 Worker의 8787은 서로 다른 서버다. Worker의 자산·번들·상태는 `.local/standalone-worker/` 아래에 만들며 DB 상태는 `state/`에 보존한다. 기존 `.local/haru-five.sqlite`를 가져오거나 덮어쓰지 않는다. 두 환경에서 자료가 자동 공유되지 않으며 어느 쪽도 시험 계정을 생성하지 않는다.

준비 runner는 추가 인자·원격 모드를 거절하며 설정을 로컬 전용 값과 대조한다. placeholder DB ID와 `remote:false`, `workers_dev:false`, `preview_urls:false`를 유지한다. 명시된 빈 환경 파일만 지정하고 `.env`·`.dev.vars`·임의 인증키를 전달하지 않는다. build gate는 **배포 실수 방지 장치이며 보안상 강제 차단이 아니다.** 소스·환경·CLI를 직접 바꿀 수 있는 사용자까지 통제하는 장치로 보지 않는다.

공개 요청은 Worker를 먼저 통과하며 고정 허용목록의 파일만 제공한다. 공개 원점이 없으면 loopback에서만 동작한다. 실제 HTTPS 원점을 설정하는 것은 별도 운영 작업이며 현재 준비 설정을 바꿔 즉시 배포하는 절차는 제공하지 않는다. 세부 구조와 운영 전 과제는 [독립 Worker 준비](standalone-worker.md)를 따른다.

2026-10-20 검증은 Wrangler 4.92.0 dry-run 번들 272.02KiB(gzip 65.19KiB), 로컬 D1의 6개 마이그레이션 적용, 서버 종료 뒤 DB 명령 재실행 시 미적용 마이그레이션 없음이다. 8787의 실제 HTTP에서 공개 파일 14개 200, DB ready, 익명 상태와 모든 로그인·가입·재인증 기능 비활성, 위조 Sites 요청 401, 비공개 경로 9개 404를 확인했다. **이 시험 서버는 종료했으며 기존 5174 서버는 유지했다.** 이번 단계에 새 브라우저 시각 검수는 하지 않았다.

이 로컬 검증은 원격 Free 플랜의 CPU·요청·DB 한도를 재현한 결과가 아니다. `cpu_ms:10`은 설정값이며 원격 실행 성능이나 월 비용 상한을 보장하지 않는다. 실제 원격 무료 호스팅과 접근 제한도 아직 구성하지 않았다. 사업자등록 전·월 3만 원 이내 조건에서 로컬 무료 검증을 유지하고 Free를 후보로 검토하며 Paid 도입은 유보한다. [호스팅·인증 예산 검토](hosting-budget.md)를 함께 확인한다.

## 데이터

- `.local/haru-five.sqlite`는 이 PC의 개발 전용 파일이며 Git에서 제외한다. 실제 운영 DB를 읽거나 가져오지 않는다.
- `drizzle/*.sql`을 이름순으로 트랜잭션 적용하고 `local_schema_migrations`에 파일명·해시만 기록한다. 두 번째 실행에서 같은 SQL을 반복 적용하지 않는다.
- 이미 적용한 SQL을 수정하거나 삭제하면 시작을 거부한다. 새 마이그레이션을 추가하고 보존된 DB에서 검증한다. 실패한 배치는 전부 롤백한다.
- 현재 마이그레이션은 0000~0005의 6개다. 0005는 기존 인증 세션과 OAuth 요청을 보존하면서 실제 인증 시각·재인증 문맥을 추가한다. 기존 세션의 `authenticated_at`은 NULL이며 게임 세션 유효성과 별개로 민감한 API에는 새 본인 확인이 필요하다.
- `local_schema_migrations`는 로컬 어댑터 전용이다. 운영 Drizzle 스키마나 D1에 새 테이블을 적용한 것이 아니다.
- 로컬 DB에도 향후 시험 자료가 생길 수 있으므로 공유 파일·공개 자산·로그에 넣지 않는다. 이 명령은 데이터 초기화 명령을 제공하지 않는다.

## 인증 설정만 점검하기

`npm run auth:check`는 허용된 8개 프로세스 환경값의 존재·형식을 검사한다. 키가 없어도 누락 항목을 확인할 수 있고 `npm run auth:check -- --json`으로 보고서를 받을 수 있다. 환경 파일 자동 읽기·실제 인증 요청·DB 변경은 없으며 비밀값을 출력하지 않는다. 정상 진단의 종료 코드 0은 준비 완료가 아니고 `launchReady:false`다.

이 진단은 게임 실행과 별개다. `dev:local`과 Worker 준비 경로는 현재 제공자 키를 실제 인증 서비스에 전달하지 않는다. 설정을 채워도 일반 가입·로그인·재인증을 열지 않는다. Google 강제 재인증은 공식 미지원으로 차단했고 카카오·네이버 실계정 왕복도 미검증이다. [연결 점검 안내](auth-connection-checklist.md)를 따른다.

## 인증과 화면

로컬 서버는 운영 환경 변수나 `.env`의 실제 제공자 비밀값을 읽지 않는다. 자체 세션을 검사하지만 세션을 자동 발급하거나 시험 사용자를 생성하지 않는다. `__Host-` 쿠키의 Secure 속성과 HTTPS 운영 원점 요구를 약화하지 않는다. 따라서 브라우저에서는 준비 중인 카카오·Google·네이버와 문의·출시 안내, 로그인 전 정보 관리·보호자 안내를 확인한다. 기능 검증은 `tests/standalone-http.test.mjs`와 기존 서버/화면 통합 테스트의 격리된 가상 자료로 수행한다.

독립 어댑터가 반환한 `sites.enabled=false`에 따라 ChatGPT 로그인 UI를 숨긴다. 상태 정보가 없을 때도 해당 버튼은 숨긴다. 기존 Sites 어댑터는 명시된 플랫폼 기능을 유지한다. 독립 API는 임의 Sites 헤더, `__Host-haru_session=sites`, 호출 옵션에 잘못 섞인 Sites ID를 계정 근거로 사용하지 않는다.

신규 가입은 독립 어댑터가 항상 닫는다. 이 제한을 해제할 때는 환경 변수만 바꾸지 않고 만 14세 이상을 확인하는 방법·필요한 동의·가입 허가를 실제 서버 계약에 연결해야 한다. `ageVerificationReady:false`, `under14EnrollmentOpen:false`를 유지하며 신규 아동 가입·보호자 연결은 제외한다. 기존 가족 자료와 권리 행사는 보존한다. [연령 정책](age-eligibility.md)을 따른다. `guardianReady=false`를 유지한다. 키나 관련 환경 변수가 있어도 `loginEnabled:false`, `reauthEnabled:false`로 신규 로그인과 재인증을 각각 닫는다.

## 독립 호스팅에 연결할 다음 단계

`handleStandaloneRequest(request, { db, env })`가 플랫폼에 독립적인 API 진입점이다. 현재 `server/worker.mjs`는 검증한 로컬 DB와 허용한 준비 설정만 전달하며 제공자 비밀키·`getChatGPTUser()`·외부 인증 헤더를 넘기지 않는다. 로컬 정적 자산·Worker 진입점은 준비했지만 호스트 계약·운영 DB 바인딩·원격 접근 제한을 만든 것은 아니다.

1. 운영 호스트·도메인·DB와 접근 제한을 선택한다. 기존 Sites와 분리한 로컬 준비 설정을 근거로 원격 운영 구성을 별도로 검토한다.
2. 새 공개 원점을 `HARU_AUTH_ORIGIN`에 설정하고 세 제공자 콜백을 등록한다.
3. 실제 세션 발급·로그아웃·계정 연결·취소를 해당 HTTPS 원점에서 검증한다.
4. 만 14세 이상 연령 확인·서버 가입 허가, 실제 제공자·재인증과 본인·기존 가족의 권리 행사·운영 예약 삭제를 검증한 뒤 가입 허용을 검토한다. 신규 아동 가입·보호자 확인 계약은 현재 출시 범위에서 제외한다.

운영 제공자 키나 DB는 이 문서에 붙여 넣지 않는다. 실제 소셜 로그인·모바일 기기·원격 D1·예약 작업·백업 복원은 아직 확인하지 않았다.

## 정보 관리·보호자 안내 미리보기

로컬 서버를 실행한 뒤 `http://127.0.0.1:5174/#guardian`에서 만 14세 이상 정책과 기존 가족 관리 안내를, `http://127.0.0.1:5174/#privacy`에서 나의 정보 관리 안내를 볼 수 있다. 로그인 전 화면의 링크와 내 정보의 링크에서도 이동한다. 신규 보호자 확인·아동 연결은 제공하지 않으며 이름·연락처·서류 입력란은 없다. 본인 탈퇴·삭제도 폐쇄 계정의 권리 행사·복구 경로가 없어 UI와 HTTP에서 모두 차단한다. 활성 기존 계정용 최근 본인 확인은 코드와 테스트로 구현했지만 실제 제공자 연결은 열지 않았다.

관리 UI에는 확인된 본인 기록 다운로드, 서버가 확인한 아동 목록·상태·기록 다운로드, 아동의 동의 철회·삭제 요청 확인창을 구현했다. 현재 로컬 서버는 실제 로그인이나 계정을 만들어 주지 않으므로 이 기능의 인증 이후 검증은 격리된 서버·화면 테스트로 수행한다. 실제 계정이나 아동 정보를 임의로 넣어 화면을 활성화하지 않는다.

상태의 공개 `playerId`와 게임 계정을 비교하고, 아동·보호자 GET 목록 및 POST에는 `X-Haru-Account`로 세션 문맥을 전달한다. 계정이 바뀌면 이전 목록을 쓰지 않으며, 탭 숨김·다른 화면 이동·로그아웃 때 개인 정보와 확인창을 비운다. 다운로드 전에도 대상과 문맥을 재확인한다. 철회·삭제 결과가 불확실하면 자동 재전송 없이 현재 상태만 다시 조회하며 접수·삭제 대기를 완료로 오인하지 않게 표시한다.

이전 UI 단계에 앱 내 데스크톱 854×801에서 로그인 전 두 화면의 안내·버튼 비활성·전환을 확인했고 콘솔 경고·오류는 없었다. 실제 기기와 로그인한 실계정의 정보 관리 UI는 미검증이다. 이전 보호자 서버 단계는 230개, 정보 관리 UI 단계는 271개, 최근 본인 확인 단계는 342개 테스트를 통과했다. 재인증 단계의 로컬 서버 재시작 후 DB ready, 익명 상태, 재인증과 세 제공자 비활성을 실제 API로 확인했다. 최신 Worker 준비 단계는 **전체 349개 테스트·구문/타입 검사·기존 Sites 5단계 빌드**를 통과했으며 별도 Worker 로컬 검증은 위 기록을 따른다. 과거 브라우저 결과를 새 Worker 시각 검수로 재사용하지 않는다. 세부 결과는 [검증 기록](codex-verification-2026-10-20.md)을 따른다.
