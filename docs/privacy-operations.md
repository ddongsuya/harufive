# 개인정보 권리·보호자 기능 운영 설명

2026-10-20, Asia/Seoul. 현재 코드의 운영 경계와 실행 방법이다. 실제 제공자·운영 예약 작업·보존 정책은 아직 구성하지 않았다. 구현 범위와 남은 제품 작업은 [보호자 구현 상태](guardian-implementation-plan.md)를 참고한다.

## 1. 공개 준비 상태

독립 서버는 `HARU_REGISTRATION_OPEN=false`, `loginEnabled:false`, `reauthEnabled:false`를 강제하고 `guardianReady:false`, `enrollmentOpen:false`를 반환한다. 키를 넣거나 아래 명령을 실행해도 가입이 열리지 않는다. 기존 계정의 서버 인터페이스와 본인 기록 다운로드·서버 확인 아동 관리 UI를 마련했다. 활성 기존 계정의 [최근 본인 확인 코드](reauthentication.md)는 준비했으나 실제 제공자 지원은 미검증이며 독립 서버에서는 닫혀 있다. 일반 이용자용 성인 최초 진입·아동 가입·실제 동의 수집은 미완성이다. 닫힌 본인 계정의 후속 재인증 경로도 미완성이어서 `selfRecoveryReady:false`다.

실제 개인정보를 받기 전에 제공자 연결, 동의 대상 아동 확인, 운영 정책과 예약 삭제를 함께 검증해야 한다. 테스트 계정·키를 운영 로그인이나 가짜 동의 성공으로 사용하지 않는다.

## 2. 외부 증빙 어댑터의 서버 설정

| 설정 | 내용 |
|---|---|
| `HARU_GUARDIAN_ATTESTATION_PUBLIC_KEY` | 고정된 RSA 공개키의 SPKI PEM. 서명 검증 전용이며 비밀키를 받지 않음 |
| `HARU_GUARDIAN_ATTESTATION_ISSUER` | 신뢰할 제공자의 정확한 HTTPS 발급자 식별자 |
| `HARU_GUARDIAN_ATTESTATION_AUDIENCE` | 하루다섯용으로 발급된 증빙의 정확한 수신자 |
| `HARU_GUARDIAN_POLICY_VERSION` | 검토한 동의 문구의 현재 버전 |

이 설정은 미래 제공자 통합 계약이다. 네 값의 형태가 채워졌다는 `providerConfigured` 상태는 실제 계약·제공자 확인·서비스 준비 완료를 뜻하지 않는다. 실제 제공자는 선정하지 않았으며 공개 준비 상태는 계속 false다.

수락하는 JWT 계약:

- 헤더: `alg: RS256`, `typ: guardian-consent+jwt`.
- 필수 표준 항목: 정확한 `iss`, `aud`; 비어 있지 않은 `sub`, `jti`; 정수 `iat`, `exp`. 증빙 유효 기간은 최대 300초이며 미래 발급·만료·요청보다 오래된 발급을 거절한다.
- 요청 연결: `requestId`, `guardianAccountId`, 생성/재발급 시 받은 `nonce`가 현재 요청과 일치해야 한다.
- 각각 명시적으로 참: `identityVerified`, `guardianAdultVerified`, `relationshipVerified`, `consentGiven`.
- `consentScopes`: `account:create`, `game:play`, `game:records`의 세 항목과 정확히 일치해야 한다. 광고 등 추가 동의 항목을 이 세 항목에 끼워 넣지 않는다.
- `policyVersion`: 요청에 고정된 버전 및 현재 서버 버전과 일치해야 한다. 버전이 바뀌면 예전 미연결 승인으로 새 아동을 활성화하지 않는다.

서명과 항목 확인 후에도 DB 변경 시각에 증빙 만료를 다시 검사한다. 같은 요청·같은 증빙의 콜백은 중복 저장하지 않고 수렴한다. 다른 요청에 `jti`를 재사용하면 차단한다. 서버에는 JWT·주체 원문 대신 증빙/JTI/주체의 해시와 최소 동의 메타데이터만 저장한다. 증빙 입력·토큰·nonce를 요청 로그나 오류 보고에 포함하지 않는다.

아동의 실제 신원/대상은 이 JWT 계약만으로 연결되지 않는다. HTTP에 없는 내부 `bindChild`를 호출하는 미래의 서버 가입 어댑터가 실제 확인 대상과 대기 계정의 일치를 보장해야 한다. 클라이언트가 아동 ID를 선택해 호출하는 경로를 추가하지 않는다.

## 3. 기존 계정용 HTTP 인터페이스

`server/standalone-http.mjs`가 `server/privacy-http.mjs`로 연결한다. 모든 경로는 HTTPS로 설정한 `HARU_AUTH_ORIGIN`과 일치해야 하며, Sites 헤더 대신 서버가 검증한 불투명 세션을 사용한다. 서명 검증한 `auth_time`에서 저장한 `authenticated_at`으로부터 15분 미만이어야 한다. 기존 DB 업그레이드의 NULL은 확인되지 않은 상태이며 `created_at`이나 토큰 `iat`를 대신 쓰지 않는다. NULL·기한 초과·미래 확인 시각은 `401 REAUTH_REQUIRED`로 거절한다.

POST는 동일한 `Origin`과 JSON 본문을 요구한다. POST 및 아동·보호자 목록 GET은 상태 조회에서 받은 `accountContext`를 `X-Haru-Account` 헤더로 요구한다. 최초 GET `/api/privacy/status`만 이 문맥 헤더 없이 새 문맥을 받을 수 있다. `accountContext`는 클라이언트가 지정하는 계정 ID가 아니다. 서버는 인증에서 얻은 64자리 세션 해시를 내부 `sessionProof`로 전달하며, HTTP 입력으로 세션 증거를 선택할 수 없다. 최종 조회·쓰기의 SQL에서 계정 일치·세션 철회·만료·`authenticated_at`의 최근 인증 기한을 재검사해 처음 인증 이후의 로그아웃 경합을 차단한다. DB의 초 단위 기한 판정은 보수적으로 처리하므로 최대 999ms 일찍 닫힐 수 있다. `sessionProof` 생략은 신뢰된 내부 서비스·유지 관리 전용이고 HTTP에서는 항상 전달해야 한다.

별도 GET `/api/auth/status`는 오래된/NULL 확인 시각의 유효 세션에도 `reauthentication`의 문맥·공개 플레이어 ID·연결 제공자별 사용 가능 여부를 반환한다. 이 응답 자체는 정보 관리 권한이 아니며, 재인증 뒤 정보 관리 상태와 권한을 다시 조회해야 한다. 상세 시작·콜백 계약은 [최근 본인 확인](reauthentication.md)을 따른다.

| 경로 | 방식 | 내용 |
|---|---|---|
| `/api/privacy/status` | GET | 본인 상태·현재 계정 문맥·공개 `playerId`·준비 상태·화면 기능 허용 여부 |
| `/api/privacy/children` | GET | 현재 문맥의 보호자에게 연결된 아동 목록과 상태. 최대 100개, 나머지 여부는 `hasMore` |
| `/api/privacy/status` | POST | 본인 또는 `childAccountId`로 지정한 가족 계정의 상태 |
| `/api/privacy/export` | POST | 본인 또는 확인된 가족 계정의 자료 내보내기 |
| `/api/privacy/withdraw` | POST | `confirmation: "withdraw"`를 포함한 철회 |
| `/api/privacy/delete` | POST | `confirmation: "delete"`를 포함한 삭제 접수 |
| `/api/guardian/requests` | GET | 본인이 시작한 유효 요청 목록. 토큰·nonce·증빙 제외 |
| `/api/guardian/create` | POST | 빈 JSON 객체로 보호자 요청 생성. 아동/보호자 연락처 필드 없음 |
| `/api/guardian/rotate` | POST | `requestId`의 토큰과 nonce 재발급. 최초 기한 유지 |
| `/api/guardian/approve` | POST | `requestId`, `requestToken`, 서명된 `attestation` 검증 |
| `/api/guardian/reject` | POST | `requestId`의 요청 및 미연결 증빙 즉시 제거 |

상태 응답의 `playerId`는 현재 계정의 게임 공개 ID 또는 프로필이 없을 때 null이다. 화면은 이를 이미 표시 중인 게임의 공개 ID와 비교한다. 아동·보호자 목록의 문맥이 누락되거나 쿠키 계정·세션이 바뀌면 서버는 목록을 내보내기 전에 `409 ACCOUNT_CHANGED`로 거절한다. 아동 목록은 `childAccountId`, 표시용 `label`, 상태와 최소 삭제 접수 요약만 제공하며 삭제 완료 계정은 제외한다. 표시 이름은 화면에 출력할 때 이스케이프한다.

권리 POST의 `childAccountId`를 생략하면 본인이다. 다른 가족의 ID를 제공해도 서버 관계 검사를 통과할 수 없다. 아동의 철회 뒤에는 연결된 보호자의 유효한 인증으로 권리를 행사한다. 응답은 개인 캐시 금지이며 내보내기에 세션·제공자 비밀 식별자·미공개 문제 스냅샷을 넣지 않는다. 본문은 24KiB 이하, 허용 필드만 받으며 호출 수는 계정의 게임 호출 수와 공유하여 분당 30회로 제한한다.

`bindChild`, 영구 삭제, 유지 관리, 삭제 정책 입력 경로는 HTTP에 없다. 삭제 접수 성공은 실제 데이터 삭제나 백업 삭제 성공을 의미하지 않는다. 본인 철회/삭제 접수 후 기존 세션이 취소되므로 해당 본인의 후속 온라인 권리 절차는 현재 사용 준비가 되어 있지 않다.

## 4. 로컬에서 정리 기능 검증하기

프로젝트의 기존 `.local/haru-five.sqlite`에 한 번 실행한다.

```powershell
npm run privacy:maintain
```

이 명령은 테스트용 DB를 새로 만들거나 운영 DB로 접속하지 않는다. 실제 경로가 프로젝트 안에 있는 기존 로컬 DB인지 확인하고, 새 마이그레이션을 적용한 다음 다음 작업을 실행한다.

1. 최초 만료 기한이 지난 보호자 요청과 아직 아동에 연결되지 않은 증빙을 제거한다.
2. 삭제 대기 작업을 확인한다. 서버 삭제 정책이 없으므로 실제 계정 삭제는 진행하지 않으며 `awaitingPolicy:true`를 반환한다.

출력은 로컬 실행임을 나타내는 `environment:"local"`, 반복 예약이 아님을 나타내는 `scheduled:false`, 삭제/대기 개수다. 명령 한 번의 성공은 운영 중 기한 내 반복 삭제의 증거가 아니다. 오류 시 개인 식별자나 토큰을 출력하지 않는다.

## 5. 실제 계정 자료 삭제를 여는 정책 계약

`createAccountLifecycle`의 서버 측 `purgePolicy` 또는 로컬 명령의 `--policy` 파일을 통해서만 삭제 정책을 받는다. 사용자의 HTTP 본문이나 환경 변수 하나로 이 검사를 건너뛰지 않는다.

```powershell
npm run privacy:maintain -- --policy "검토한-로컬-정책.json"
```

위 명령은 검토한 정책 파일을 마련한 뒤에만 사용하는 실행 형식이다. 예시 이름의 파일이나 운영 승인용 예시 값을 자동 생성하지 않는다. 정책 파일은 16KiB 이하의 JSON이며 다음 항목을 모두 갖춰야 한다.

| 항목 | 현재 검사와 운영자가 정할 내용 |
|---|---|
| `version` | 숫자 `1` |
| `eraseGameAndAccountData` | `true`: 현재 DB의 게임·인증 자료 삭제 범위 동의 |
| `eraseGuardianEvidence` | `true`: 대상의 보호자 요청·관계·동의 증빙 삭제 범위 동의 |
| `retainMinimalClosureRecords` | `true`: 재생성 차단 행과 최소 접수 기록의 별도 보존을 인정 |
| `policyId` | 검토한 정책을 찾을 수 있는 식별 설명 |
| `closureRetention` | 계정 차단 기록의 보존 기간·근거·정리 방식 설명 |
| `receiptRetention` | 최소 삭제 접수/완료 기록과 요청 주체 해시의 보존 설명 |
| `backupReplayProcedure` | 백업 보유·복원 후 차단/삭제 재적용 절차 설명 |

마지막 네 문자열은 앞뒤 공백을 제외한 최소 8자, 최대 2000자인지 검사한다. **이는 형태 검사이며 법률 검토·운영 승인·실제 백업 절차의 실행을 자동 확인하는 기능이 아니다.** 설명 문자열을 채웠다고 보존 정책이 스케줄러에 적용되거나 백업이 삭제되지 않는다. 운영자가 범위·기간·실행 담당·증거를 정하고 별도 절차를 구현해야 한다.

현재 코드에는 계정 차단 행과 최소 완료 기록을 자동 만료시키는 기능이 없다. 이 자료를 무기한 보유하기로 확정한 것은 아니다. 장기 보존 기간과 정리 방법은 미정이며, 실제 개인정보 처리 전 결정하고 구현해야 한다. 테스트 파일의 정책 문자열은 기능 시험용이며 운영 정책으로 사용하지 않는다.

## 6. 삭제 범위와 재시도

삭제 정책을 가진 실행은 기본 25개 작업을 처리한다. 서버 메서드 `processDeletionJobs({limit})`의 범위는 1~100이며 로컬 CLI가 이 값을 사용자 입력으로 받지는 않는다. 각 작업은 하나의 트랜잭션이다. 중간에 실패하면 자료와 작업 상태가 함께 되돌아가고 다음 실행에서 다시 처리할 수 있다.

현재 DB에서 제거하는 것은 게임 프로필과 외래키로 연결된 시도·결과·코인 원장·중복 처리 영수증·개인별 주간 보상, 게임 호출 제한, 인증 계정과 소셜 연결·세션·관련 OAuth 진행 상태, 대상의 보호자 요청·동의 증빙·관계다. 게임 계정과 인증 계정은 독립된 루트이므로 둘 다 삭제한다. 관리가 필요한 아동이 남아 있는 보호자 자신의 삭제는 차단한다.

전체 주간 정산 마감 기록은 유지한다. `privacy_account_controls`의 `deleted` 행과 `privacy_deletion_jobs`의 최소 완료 기록도 유지한다. 요청 주체는 `sha256:` 해시로 기록하고, 처리한 보호자가 삭제 이후 최소 완료 상태를 확인하는 데 사용한다. 이 기록은 완전한 익명 정보라고 단정하지 않는다.

완료 응답의 범위는 `scope:"live-database"`, `backupReplayRequired:true`다. 외부 제공자 저장 자료, 로그, 캐시, 스냅샷, 백업까지 제거했다는 뜻이 아니다. 미정인 보존 범위를 임의로 확정하지 않는다.

## 7. 운영 연결과 복구 검증 과제

운영 스케줄러는 사용자 방문과 무관하게 만료 정리를 실행해야 한다. 요청은 최초 생성 후 5일로 고정되지만, 실제 제거는 정리 작업이 실행되어야 일어난다. 현재 로컬 명령만으로 5일 이내 제거를 보장하지 않는다. 기한을 넘기기 전 여유를 둔 실행 주기, 장애 재시도, 가장 오래된 미정리 요청 감시, 누락·실패 경보와 실제 삭제 증거를 운영 환경에 연결해야 한다.

백업을 복원한 DB를 서비스에 연결하기 전에 보존된 폐쇄 상태와 삭제 작업을 재적용하는 절차도 필요하다. 현재 자동 백업 처리·복원 후 재삭제 도구는 없다. 원래 기록을 되살린 뒤 공개 서비스에 먼저 연결하면 삭제 계정이나 세션이 복원될 수 있으므로 복구 절차의 검증이 끝날 때까지 운영 준비 완료로 표시하지 않는다.

검증할 주요 경계는 서명/주체/관계 불일치, 오래된 세션, 다른 출처, 다른 계정 문맥, 가족 간 접근, 미연결 증빙 만료, 재발급 기한, DB 대기 중 만료, 철회와 게임 쓰기의 경쟁, 삭제 실패 후 재시도, 복원 후 재삭제다. 제공자·운영 DB·예약 작업·백업 검증은 로컬 테스트와 별도의 증거로 기록한다.

## 8. 정보 관리 UI의 동작과 검증 범위

로그인 전 `#guardian`은 보호자 확인·동의·아동 연결의 준비 절차와 문의를 안내한다. 실제 확인 시작 버튼은 비활성이며 이름·연락처·인증 서류를 받지 않는다. `#privacy`도 로그인 전에는 안내만 제공하고 개인정보 관련 버튼을 잠근다.

최근 본인 확인을 통과한 기존 계정의 관리 화면은 서버의 `capabilities`를 따르며 현재 `selfExport:true`, `childManagement:true`, `selfClosure:false`, `guardianEnrollment:false`다. 본인 기록과 서버가 확인한 연결 아동만 표시한다. 자기 탈퇴·삭제 버튼은 항상 비활성이고 폐쇄 계정의 후속 권리 절차가 준비되지 않았음을 설명한다. 활성 기존 계정의 재인증 준비는 이 제한을 해제하지 않는다. 아동 ID나 동의 대상 정보를 자유롭게 입력해서 연결하는 UI는 없다.

아동을 선택해 자료를 받거나, 대상과 영향을 확인한 뒤 동의 철회·삭제 접수를 요청할 수 있다. 철회·삭제 확인창을 열었더라도 계정 문맥이나 선택 아동이 바뀌면 제출하지 않는다. 내보내기도 다운로드 직전에 문맥·현재 공개 플레이어 ID·선택 아동이 유지되는지 확인한다. 변경 응답이 불확실하면 자동 재전송을 하지 않고 상태 다시 확인만 제공한다. `deletion_pending`은 접수·대기 상태이며 전체 삭제 완료로 표시하지 않는다.

탭 숨김·화면 이탈·로그아웃·계정 변경에서는 개인 상태와 확인창을 지우고 대기 중인 요청을 취소한다. 이전 계정에서 늦게 도착한 응답은 무시하며 복귀할 때 게임·인증·정보 관리 상태를 새로 확인한다. `public/game/privacy.js`는 문맥과 아동 선택 목록을 메모리에만 보관하고 브라우저 쿠키를 직접 만들거나 읽지 않는다. 응답 크기는 일반 정보 256KiB, 내보내기 4MiB로 제한하며 제한 초과·잘못된 상태·취소·지연은 오류로 처리한다.

최근 본인 확인이 필요하면 서버가 허용한 기존 연결 제공자만 선택한다. 시작 전 문맥과 공개 플레이어 ID를 다시 확인하고, 콜백 뒤 인증·게임·정보 관리 상태를 다시 조회한다. URL의 성공 표시는 권한이 아니며 이전 철회·삭제 요청을 자동 재실행하지 않는다. 독립 서버의 실제 제공자 재인증은 계속 비활성이다. 로그인 후 재인증 UI의 자동 검사는 테스트 자료 기반이며 실제 제공자 브라우저 왕복을 검증한 것이 아니다.

확인한 브라우저 범위는 앱 내 데스크톱 854×801에서 로그인 전 `#guardian`·`#privacy` 안내, 버튼 비활성, 화면 전환과 콘솔 경고·오류 없음이다. 실제 기기·실제 로그인 후 관리 UI·외부 제공자 확인은 아직 검증하지 않았다. 테스트 자료로 통과한 화면·서버 검증과 실제 사용자 검증을 구분하며 최종 결과는 [검증 기록](codex-verification-2026-10-20.md)에 기록한다.
