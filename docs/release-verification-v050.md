# v0.5.0 배포 준비 검증 기록

검증일: 2026-10-20 한국시간. 대상은 이 문서와 함께 저장한 v0.5.0 서버 전환 소스다. 기존 소유자 비공개 Sites 프로젝트에 배포하는 준비 작업이며 일반 공개·등급분류·결제 승인을 증명하는 문서는 아니다.

## 통과한 실행

| 실행 | 결과 | 범위 |
|---|---|---|
| `npm test` | 105개 통과, 실패·취소·건너뜀 0 | 파일별 Node 프로세스에서 기존 회귀와 새 서버/HTTP/화면 실행 |
| `npm run check` | 통과 | 공개 컨트롤러·전송·서버 서비스·HTTP 구문과 TypeScript 검사 |
| Sites 공식 `build-site.mjs` | 통과 | Vinext/Vite 5단계 Worker·RSC·SSR·클라이언트 빌드 |
| 배포 공개 자산 검사 | 통과 | 공개 코드에 문제은행·출제·채점·DB 테이블·내부 문항 ID 필드가 포함되지 않음 |
| 그림·소리·캘린더 모듈 비교 | 원본과 동일 | v0.4.0 도트 렌더러·오디오·캘린더 코드의 바이트 동일성 |

빌드된 경로는 동적 `/`, 게임 API `/api/game/:action`, 상태 확인 `/api/health`다. 브라우저 컨트롤러는 빌드가 추적하는 모듈로 연결하고 화면의 React effect에서 `mountGame()`을 실행한다. 공개 디렉터리의 원본과 빌드 복사본도 동일함을 확인했다.

새 서버 테스트는 `tests/server-game.test.mjs` 16개, HTTP 테스트는 `tests/server-http.test.mjs` 13개다. `tests/release-ui.test.mjs`는 Node 집계상 12개이며 실제 공개 컨트롤러, API 전송, 완료·연습 흐름을 다룬다. 나머지는 `legacy/v040/`를 대상으로 한 기존 8개 파일의 회귀 검증이다. 기존 가상 랭킹·모의 광고 테스트가 새 서비스에 존재한다는 뜻은 아니다.

## 실제 DB로 확인한 동작

테스트 DB는 배포와 같은 `drizzle/0000_chemical_albert_cleary.sql`을 Node의 실제 SQLite에 적용한다. 문자열만 비교하는 SQL 모형을 쓰지 않는다. D1의 prepare/batch 모양을 어댑터로 제공하고, 배치는 실제 BEGIN/COMMIT/ROLLBACK으로 실행한다.

- 동시에 최초 프로필·도전을 요청해도 시작 코인과 하루 시도는 하나다.
- 마지막 답안 20개를 동시에 재전송해도 완료 결과와 일일 20코인 지급은 각각 한 번이다.
- 배치 마지막에 실제 SQL 오류를 일으키면 잔액·결과·시도·원장·요청 영수증이 함께 롤백된다.
- 잔액보다 큰 두 상품을 동시에 사도 음수 잔액이나 공짜 소유권이 생기지 않는다.
- 타 계정의 시도 ID는 사용할 수 없다. 내보내기에는 본인의 완료 기록만 들어가며 내부 인증 ID와 미래 문항은 제외된다.
- 기억 문제 준비·고정 배열 노출 동안의 조기 답변, 재노출, 노출 종료 연장을 막는다.
- 일요일 최종 제출의 배치를 지연한 사이 월요일 정산을 완료하면 지연 제출은 `WEEK_CLOSED`로 거부된다.
- 92일의 실제 완료 기록에서 조회는 최근 90개, 누적은 92일/460문제, 내보내기는 92개를 유지한다.
- 실제 105개 계정을 완료한 뒤 상위 100명과 본인 105위 행을 분리해 반환한다.

## HTTP와 화면

인증이 없는데 외부 헤더나 쿠키로 계정을 주장하는 요청, 다른 출처의 요청, 허용되지 않은 메서드·필드·JSON 형식, 4KiB 초과 스트림을 거부한다. 내보내기·게임 응답은 개인 데이터 캐시를 금지한다. 예상하지 못한 DB 오류에는 SQL·스택·인증 ID를 반환하지 않는다.

계정별 분당 120개 요청까지 허용하고 이후에는 429와 Retry-After를 반환한다. 다른 계정의 사용량은 섞이지 않는다. 화면은 대기 중 중복 클릭을 막고, 연결 실패 때 선택과 요청 ID를 유지하며, 429 대기 시간을 지킨다. 401을 받으면 개인 화면과 열린 모달을 비운다.

화면의 실제 클릭 핸들러로 공식 다섯 문제 → 서버 결과·해설 → 무료 연습 다섯 문제를 끝까지 실행했다. 이 케이스는 fetch 응답 예시만 사용하는 검증과 별도로 **실제 HTTP 핸들러 → 게임 서비스 → SQLite**를 연결한다. 공식 완료 보상은 한 번 지급되고 무료 연습은 코인과 공식 통계에 반영되지 않았다.

## 검토에서 발견하고 수정한 결함

| 결함 | 수정과 재현 결과 |
|---|---|
| 서버 내부 요청 제한 DB 지연이 풀이 시간에 더해짐 | 답안 본문을 모두 받은 시각을 채점에 전달. 1,200ms 풀이 + 5,000ms 내부 지연을 1,200ms로 기록한다. |
| 완전한 답변 전 시간을 고정하면 지연 스트림으로 시간 단축 가능 | 본문 끝까지 받은 뒤 시각을 잡는다. 마지막 바이트를 5,000ms 늦추면 6,200ms로 기록한다. |
| 취소된 React 마운트의 늦은 모듈 로딩이 새 화면을 덮을 수 있음 | import 부작용을 제거하고 명시적 `mountGame()`·`destroy()`로 수명을 관리한다. 최종 연결은 정적 모듈 import를 사용한다. |
| 이전 분의 지연 요청이 현재 분의 제한 카운터를 초기화함 | 저장된 분보다 새 분일 때만 초기화한다. 새 분 120건 뒤 옛 요청과 추가 요청이 모두 429이고 현재 분은 유지된다. |
| Vinext가 무시된 동적 public import를 SSR 분석에서 잘못 해석함 | 원본 컨트롤러를 빌드에 포함하는 정적 import로 변경하고 전체 배포 빌드를 다시 통과했다. |

## 수행하지 않은 검증과 남은 공개 조건

현재 개발 환경에는 Sites가 지원하는 브라우저 제어 기능이 없다. 대체 브라우저를 설치하거나 비공식 미리보기 서버를 실행하지 않았다. 따라서 실제 브라우저의 로그인 왕복, CSS 글꼴·카드 겹침, 320px 모바일 배치·터치, 픽셀 캔버스 출력, 오디오 청음과 캘린더 알림 수신은 이 결과에 포함되지 않는다. DOM 하니스의 마크업 검사는 픽셀 배치 검사와 다르다.

SQLite 통합 검증은 실제 D1 운영의 부하·다중 지역 네트워크·백업 복구 실습을 대체하지 않는다. `/api/health`와 인증 없는 API의 실제 운영 HTTP 응답은 배포 후 별도로 확인한다. 이를 위해 실제 사용자로 가장하거나 인증 헤더를 임의로 주입하지 않는다.

실제 광고 SDK·현금 결제·웹푸시·계정 삭제 운영 흐름, 문항 난이도 보정과 운영자 도구, 법적 등급분류·사업자·개인정보 고지 준비는 남아 있다. 구체적인 운영 결정과 기관 문의 초안은 [정식 공개 준비 문서](release-readiness-v050.md)를 따른다. 이번 배포는 기존 소유자 접근 범위를 유지한다.
