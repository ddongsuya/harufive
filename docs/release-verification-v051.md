## 이번 검증에서 수정한 문제

1. **예전 탭의 계정 혼동:** 로그인 계정이 바뀐 뒤 기존 화면이 구매·답안 제출을 보내는 경우를 차단했습니다. 변경 요청과 내보내기에는 화면이 알고 있는 공개 플레이어 ID를 요구하고 현재 인증 계정과 일치하는지 서버에서 확인합니다. 불일치하면 변경 없이 `ACCOUNT_CHANGED`로 다시 동기화합니다.
2. **로그아웃 응답 유실:** 서버 처리 여부를 확인할 수 없어도 개인 기록과 코인 화면은 즉시 가립니다. 결과 확인 전 다른 로그인·게임 요청을 막고 같은 로그아웃을 다시 확인할 수 있습니다.
3. **인증 교환과 취소의 경쟁:** 외부 제공자의 응답을 기다리는 동안 로그아웃하거나 새 인증을 시작하면 이전 콜백이 새 계정·연결·세션을 확정할 수 없도록 했습니다. 이미 발급됐으나 아직 브라우저에 도착하지 않은 세션도 연결 해시로 철회할 수 있습니다.
4. **만료 후 다른 계정으로 전환:** 소셜 로그인 쿠키가 없어지거나 만료돼도 기존 Sites 계정으로 자동 전환하지 않습니다. ChatGPT를 이용할 때도 게임 내부에서 해당 로그인 수단을 명시적으로 선택합니다.
5. **인증 조회 시간이 점수에 포함되는 문제:** 답안 본문을 완전히 받은 시각을 저장한 뒤 인증·게임 계정·요청 제한 DB 조회를 실행합니다. 인증 DB가 늦어지는 시간은 풀이 시간에 더하지 않으며 답안을 천천히 전송하는 시간은 포함합니다.

## 인증·데이터 경계

- 검증한 제공자 식별자만 게임 계정에 연결합니다. 같은 이메일이라는 이유로 계정을 합치지 않습니다.
- 제공자 토큰·이메일·이름은 게임 DB에 저장하지 않습니다. Google의 `openid email` 요청에서 이메일을 받는 것과 저장하지 않는 것은 구분합니다.
- 외부 제공자 비밀값은 서버 환경 변수로만 설정합니다. 소스의 `.env.example`에는 키 이름과 공개 가입 비활성 기본값만 있습니다.
- 새 인증 테이블 5개를 기존 게임 테이블 8개에 추가합니다. 이전에 적용한 SQL을 수정하지 않고 3개 후속 마이그레이션을 추가했습니다.
- 상태 API는 버전·DB 준비 상태 또는 제한된 로그인 상태만 응답합니다. 이메일·내부 계정 ID·제공자 비밀값을 포함하지 않습니다.
- 일반 신규 가입은 `HARU_REGISTRATION_OPEN=false`입니다. 기존 계정과 서버에서 확인한 단일 소유자 테스트 허용 설정만 비공개 개발 환경에서 이용할 수 있습니다.
- 목표 게임 등급은 전체이용가입니다. 실제 등급분류, 가입 연령 정책, 보호자 동의·확인 절차를 완료했다는 뜻이 아닙니다.

| 항목 | 현재 상태 |
|---|---|

| 실제 제공자 로그인·취소·다시 로그인·기존 계정 연결 | 실계정과 제공자 콘솔 설정 후 확인 필요 |
| 휴대폰 화면 겹침·터치·캔버스 출력 | 지원되는 브라우저 제어 기능이 없어 실제 기기 검증 미실시 |
| 실제 소리 청음·캘린더 알림 수신 | 미실시. 현재 알림은 캘린더 일정 파일이며 서버 Web Push가 아님 |
| D1 운영 백업 복구·다중 지역 지연·대규모 트래픽 | 별도 운영 검증 필요 |
| 계정 탈퇴·정보 삭제·보유기간·보호자 동의 | 정책 확정과 실제 처리 구현 필요 |
| 광고·결제 | 실제 광고 SDK와 결제 서비스 연결 없음 |

운영 설정과 각 제공자의 정확한 콜백 주소는 [소셜 로그인 준비 문서](social-login-launch.md), 공개 출시 준비는 [출시 준비 문서](release-readiness-v050.md)에 정리했습니다. 코드 버전을 되돌려도 DB 마이그레이션은 자동으로 되돌아가지 않습니다.
