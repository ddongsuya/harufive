**현재 수익화 결정 (2026-10-20):** 무료 플레이와 광고 수익만 목표로 한다. 현금 상품·유료 코인·후원형 과금과 PG·판매 환불 구현은 범위에서 제외하고, 플레이로 얻는 게임 코인 상점은 유지한다. 광고 SDK는 미연결이다. 이 변경으로 실제 소셜 계정 연결·연령 확인·권리 행사와 등급·사업자등록 준비를 생략하지 않는다. [광고 수익화 정책](ad-only-policy.md)을 우선한다.

아래 구현·배포 설명은 v0.5.1 준비 당시 기록이다. 이후 로컬 개발과 검증 결과는 [최신 검증 기록](codex-verification-2026-10-20.md)에서 확인한다.

**실제 사이트는 소유자 비공개 v0.5.0이다. v0.5.1의 원격 저장·배포는 차단되어 있으며, 이 문서의 v0.5.1 동작은 준비한 소스에 관한 설명이다.** 문의 연락처·가입 대상의 확정으로 차단이 해제되거나 새 버전이 배포된 것은 아니다.

## 2. 전체이용가 목표와 만 14세 이상 운영

전체이용가는 게임 내용에 따른 목표 등급이다. 등급 취득, 회원가입 연령 확인, 개인정보 처리와 플랫폼 이용 조건을 대신하지 않는다. [게임산업법 제21조 제1항][rating-process] [제2항][rating-definition]

만 14세 미만 신규 가입·이용과 보호자 연결은 출시 범위에서 제외한다. 소셜 로그인이나 화면 체크 표시만으로 만 14세 이상이 확인됐다고 처리하지 않는다. 필요한 연령 확인 방법·증거·보관을 정하고 서버의 가입 허가에 연결해야 한다. 불필요한 상세 생년월일·전화번호를 먼저 수집하지 않는다.

만 14세 이상도 청소년·미성년자일 수 있다. 게임산업법 청소년 가입 규정과 시행령의 적용 범위·예외는 실제 운영 주체·매출·제공 방식으로 확인한다. 유료 휴대전화 본인인증이 필수라거나 모든 보호자 동의가 면제됐다고 단정하지 않는다. [연령 정책과 법령 근거](age-eligibility.md)

기존 가족 관계와 자료는 정책 변경으로 삭제하거나 연령을 추정해 수정하지 않는다. 권한 있는 열람·내보내기·철회·삭제와 만료 정리는 유지한다. 신규 보호자 요청 생성·재발급·승인은 공개 HTTP에서 열지 않는다.

현재 Sites의 접근 범위와 계약 조건, 정식 호스팅·도메인 검토는 별개다. 만 14세 이상으로 바꿨다고 기존 플랫폼의 공개 승인이나 배포 권한이 자동 확보되지는 않는다. [Sites 안내][sites]

선택 이력은 같은 날 10:12 KST의 B안에서 **후속 사용자 지시의 만 14세 이상 정책으로 변경**한 것이다. 이전 B안에 필요한 아동 가입 어댑터·보호자 확인 계약을 현재 필수 출시 작업으로 두지 않는다.

## 3. 소셜 로그인과 사이트 공개는 별개의 설정

현재 주소는 <https://haru-five.limjm900202.chatgpt.site>다. Sites의 공유 설정은 누가 주소를 열 수 있는지를 결정하고, 하루다섯 내부 로그인은 열린 사이트에서 누구의 게임 기록을 사용할지를 결정한다. 공식 안내도 이 두 제어를 구별한다. [OpenAI의 Sites 로그인 안내][sites]

소유자 비공개 상태에서는 카카오·구글·네이버 로그인 코드를 연결해도 일반 이용자가 사이트 접근 제한을 통과할 수 없다. 인증 제공자의 심사 담당자가 사이트를 검수할 수 있는 경로도 따로 마련해야 한다. 코드 배포, 소셜 로그인 연결, 신규 가입 허용, 공개 대상 변경을 하나의 완료 상태로 표시하지 않는다.

## 4. 계정 연결 원칙

하나의 게임 계정에 여러 인증 수단을 연결한다. 이메일 주소가 우연히 같다는 이유만으로 서로 다른 로그인 수단의 계정을 합치지 않는다. 기존 게임 계정으로 로그인한 이용자가 새 제공자에서 본인 인증을 마친 뒤 연결하도록 구현한다.

이미 다른 게임 계정에 연결된 제공자 계정은 자동 이동하거나 두 계정의 점수·코인을 합산하지 않는다. 로그인 수단을 추가할 때도 하루 도전 횟수와 보상 기록을 새로 만들지 않아야 한다. 기존 ChatGPT 인증으로 사용하던 기록은 기존 계정에 연결해 유지한다.

로그인 제공자는 비공개 계정 식별에 사용한다. 실명·이메일·프로필 사진을 공개 랭킹에 자동 반영하지 않는다. 현재 목표에 필요하지 않은 연락처·성별·생일 같은 동의항목은 추가하지 않는다. 실제 구현이 어떤 정보를 요청·수신·저장하는지 확인한 뒤 처리방침에 반영한다.

### 업그레이드 후 로그인 선택과 기존 탭

다음은 v0.5.1이 배포된 뒤 적용할 동작이며, 현재 실제 사이트는 v0.5.0이다. 게임의 인증 쿠키가 없으면 로그인 선택 화면을 보여 준다. 기존 소유자도 v0.5.1 업그레이드 후 **ChatGPT 로그인을 한 번 선택**해야 한다. 선택 시 서버에 POST로 인증 시작을 요청해 Sites 인증 모드 쿠키를 설정한 뒤, 기존 Sites의 정상 로그인 링크를 따른다. 이렇게 다시 로그인해도 v0.5.0에 저장된 게임 기록은 유지한다.

소셜 로그인 세션의 만료는 7일이다. 세션이 만료되거나 쿠키가 삭제되면 로그인 선택으로 돌아간다. 같은 브라우저에 별도의 Sites 인증이 남아 있더라도 다른 계정으로 자동 전환하지 않는다.

게임 상태를 변경하는 POST와 내 데이터 내보내기에는 `X-Haru-Player`가 필요하며, 이 값이 서버에서 인증한 계정의 공개 게임 식별자와 일치해야 한다. 이 헤더 자체를 인증으로 신뢰하는 것은 아니다. 이전 v0.5.0 화면이 열린 탭은 새 계약을 사용하지 않으므로 **새로고침 후 계속 이용**해야 한다. 오래된 탭에서 보던 기록과 현재 로그인 계정이 어긋난 상태로 구매·답안 제출·내보내기를 진행하지 않도록 하는 장치다.

## 5. 서버 설정과 콜백 주소

카카오·구글·네이버용 실제 자격 증명은 미설정이다. v0.5.1 소스에서 세 제공자는 연결 준비 상태이며 실제 인증 왕복을 완료한 것으로 표시하지 않는다. 가입·이용 대상은 만 14세 이상으로 변경했지만 실제 연령 확인·일반 가입·신규 보호자 등록은 닫혀 있다.

| 환경 변수 | 설정할 값·역할 |
|---|---|
| `HARU_AUTH_ORIGIN` | 현재 준비 환경에서는 `https://haru-five.limjm900202.chatgpt.site`. 경로가 없는 정확한 HTTPS 원점 |
| `HARU_GOOGLE_CLIENT_ID` | 운영자 Google 앱의 웹 클라이언트 ID |
| `HARU_GOOGLE_CLIENT_SECRET` | 같은 Google 웹 클라이언트의 비밀값 |
| `HARU_KAKAO_CLIENT_ID` | 운영자 카카오 앱의 REST API 키 |
| `HARU_KAKAO_CLIENT_SECRET` | 같은 카카오 앱의 Client Secret |
| `HARU_KAKAO_OIDC_ENABLED` | 카카오 콘솔에서 OpenID Connect ON을 확인한 뒤 문자열 `true`로 설정. 현재 `false`이며 키만 넣어서는 카카오 로그인이 활성화되지 않음 |
| `HARU_NAVER_CLIENT_ID` | 운영자 네이버 로그인 애플리케이션의 Client ID |
| `HARU_NAVER_CLIENT_SECRET` | 같은 네이버 애플리케이션의 Client Secret |
| `HARU_REGISTRATION_OPEN` | 일반 신규 가입 허용 여부. 현재 `false`. 실제 연령 확인·가입 허가·권리 행사·삭제 및 운영 준비를 검증한 뒤 전환 검토. 이 값만으로 미확인 신규 계정을 허용하지 않음 |
| `HARU_SITES_TESTER_EMAIL` | 선택적 서버 비밀 설정. 인증된 단일 Sites 소유자의 시험 계정을 허용하는 값. 운영 문의 연락처와 별개의 인증 목적이며, 이 문서에는 비밀 설정의 실제 값을 옮기지 않음 |

값은 서버 환경에만 설정한다. `NEXT_PUBLIC_` 등의 공개 변수에 복사하지 않고, 예시 비밀값을 실제 값처럼 입력하지 않는다. 공개 설정 응답에는 공급자 이름과 사용 가능 여부만 필요한 범위로 제공한다.

`HARU_SITES_TESTER_EMAIL`은 신뢰된 `getChatGPTUser()`의 인증된 이메일과만 비교한다. 브라우저가 전송한 이메일이나 임의 헤더로 허용 여부를 판단하지 않는다. 등록을 닫은 상태에서도 지정한 소유자에게 기존 v0.5.0 DB 기록이 없다면 최초 시험 계정을 만들 수 있게 하는 좁은 예외다. 다른 신규 Sites 이용자와 신규 소셜 계정의 가입은 계속 닫혀 있다. 이번에 사용자가 공개 연락처로 지정한 이메일과 시험 허용 설정에 같은 문자열을 쓰더라도 목적과 접근 제어는 별개다. 공개된 문의 주소를 알고 있는 것만으로 시험 계정 권한을 얻을 수 없다.

## 6. 외부 연결에 필요한 운영자 준비

개발자는 서버 처리·화면·설정 방법을 준비한다. 실제 운영자가 소유·관리할 인증 제공자 앱은 운영자 계정에서 등록하고, 각 제공자가 요구하는 서비스 정보와 심사 자료를 제출한다. 개발자 비밀값을 소스 코드, 브라우저 번들, 화면 캡처, 일반 대화 본문에 넣지 않는다.

| 공통 준비 항목 | 실제로 준비할 내용 |
|---|---|
| 서비스 표시 정보 | 서비스명 하루다섯, 실제 로고, 사용자가 이해할 수 있는 서비스 설명 |
| 운영 연락처 | 지정 주소 **limjm900202@gmail.com**의 수신·답변 시험, 문의·개인정보 권리 행사 담당과 처리 절차 확인 |
| 운영 주소 | 최종 서비스 도메인, 로그인 콜백 주소, 검수자가 확인할 서비스 접근 경로 |
| 이용자 고지 | 실제 수집 항목·목적·보유·삭제·제공자 처리를 반영한 개인정보처리방침과 이용약관 |
| 제공자 설정 | 서비스용 앱 및 키, 허용 도메인·콜백, 필요한 최소 동의항목, 테스트 계정과 공개 심사 상태 |
| 서버 비밀값 | 각 제공자의 클라이언트 ID와 비밀값을 호스팅 환경의 비밀 설정으로 주입 |
| 실제 검증 | 승인·거절·취소·중복 콜백·로그아웃·재로그인·계정 연결을 실제 계정으로 확인 |

로그인 코드가 준비된 뒤에도 위 항목이 없으면 해당 제공자는 준비 중 상태로 둔다. 이용자를 동작하지 않는 외부 인증 화면으로 보내거나 모의 로그인으로 실제 계정 저장을 흉내 내지 않는다.

### 제공자별 콘솔과 공개 확인

| 제공자 | 콘솔에서 준비할 내용 | 일반 이용자 연결 전에 확인할 점 |
|---|---|---|
| 구글 | 웹 애플리케이션용 OAuth 클라이언트, 지원 이메일, 정확한 콜백, 서비스명·로고·소개·처리방침 URL | 시험과 운영 프로젝트를 구분. 운영용 공개 소개 페이지와 도메인 소유권 검증을 준비하고, 브랜드 표시·요청 권한에 적용되는 검증 절차 확인. [공식 운영 정책][google-production] [브랜드 검증][google-brand] |
| 카카오 | 카카오 로그인 ON, OpenID Connect ON, 리다이렉트 URI, REST API 키와 Client Secret | 새 REST API 키는 Client Secret이 기본 활성화된다. 기본 로그인과 비즈 앱·추가 개인정보 동의항목 권한 신청을 구별하고 필요한 항목만 설정. [공식 설정 안내][kakao-setup] |
| 네이버 | 네이버 로그인 애플리케이션, Client ID·Secret, 서비스 URL·콜백, 서비스명·로고, 관리자·테스터 | 모든 사용자에게 열기 전에 사전 검수 통과가 필요. 로그인부터 가입 완료까지의 화면 자료를 준비하고 추가 정보는 실제 활용처가 있을 때만 요청. 별도 게임 비밀번호를 요구하지 않음. [공식 사전 검수][naver-review] |

Google은 OAuth 소개·정책·콜백에 사용하는 도메인 검증을 요구하며 공유 도메인을 쓰는 경우 자체 도메인 설정을 권장한다. 현재 `chatgpt.site` 하위 주소에서 검증 요건을 충족할 수 있는지는 확인되지 않았다. 주소가 동작한다는 사실을 도메인 검증 완료로 취급하지 않으며, 현재 주소로 검증이 불가능하다거나 새 도메인을 반드시 구매해야 한다고 미리 단정하지 않는다. 최종 호스팅·운영 도메인 선택과 함께 확인한다. [Google 운영 정책][google-production]

처리방침에는 요청 권한과 실제 저장을 구분해 적는다. 예를 들어 Google 연결이 `openid email`을 요청하면 이메일을 DB에 저장하지 않더라도 인증 과정에서 이메일을 요청·수신할 수 있으므로 “이메일을 요청하지 않는다”고 고지할 수 없다. 최종 안내는 구현된 scope와 토큰 검증·폐기 동작을 대조해 작성한다. 카카오·네이버에도 실제 사용하지 않는 프로필·이메일·연락처 권한을 관성적으로 추가하지 않는다.

## 7. 구현 검증과 남은 운영 기능

이번 인증 설계는 공통 계정, 제공자 식별자 연결, 서버 세션, 일회용 인증 거래를 따로 관리한다. 기존 Sites 이용자의 비공개 게임 식별자를 유지하는 연결 방식을 사용하므로, 인증 수단 추가가 게임 기록을 새로 시작시키는 동작이 되어서는 안 된다. 기존 기록 유지 여부는 마이그레이션과 계정 연결 테스트에서 확인한다.

DB는 기존 게임 테이블 8개에 인증 테이블 5개를 더해 총 13개다. 기존 적용 마이그레이션 `0000_chemical_albert_cleary.sql`은 유지하고 다음 마이그레이션을 순서대로 추가한다.

| 마이그레이션 | 추가 내용 |
|---|---|
| `0001_purple_hiroim.sql` | 계정·제공자 식별자·OAuth 거래·인증 요청 제한·세션의 인증 테이블 5개 |
| `0002_wealthy_shiver_man.sql` | OAuth 거래의 일회 처리 소유권을 확인할 `claim_token` |
| `0003_happy_rocket_racer.sql` | 인증 세션의 브라우저 연결을 확인할 `binding_hash`와 조회 인덱스 |

자동 검증에 사용하는 가짜 제공자 응답이나 서명된 시험용 OIDC 토큰은 서버 검증 로직을 시험하기 위한 자료다. 실제 제공자 콘솔 등록·심사 승인·실제 브라우저에서의 Google·Kakao·Naver 로그인 성공을 대신하지 않는다. 배포 결과와 테스트 수치는 최종 검증 보고를 따른다.

| 아직 마련해야 하는 항목 | 공개 전에 확인할 결과 |
|---|---|
| 실제 소셜 로그인 | 제공자 앱의 실제 키·등록 도메인·콜백·심사 상태와 허용된 실제 이용자의 로그인 왕복 |
| 계정 연결 해제 | 어떤 로그인 수단을 제거할 수 있는지, 남은 접근 수단 확인, 세션 무효화와 이용자 안내 |
| 제공자 연결 해제 통지 | 제공자별 해제·탈퇴 통지 지원 및 필요한 수신·검증·게임 계정 처리 방식 |
| 게임 계정 탈퇴·삭제 | 요청자 확인, 공개 프로필·게임 기록·인증 연결·세션 삭제, 합당한 보존·백업 반영 및 이용자 고지 |
| 운영 정책과 권리 행사 | 실제 문의 수신 경로, 수집·처리·보유·삭제 정책과 이용자가 요청할 수 있는 방법 |
| 연령 확인·호스팅 | 만 14세 이상 정책을 실제 서버 가입 허가에 연결하고, 청소년 관련 규정·제공자 조건과 정식 호스팅·도메인 검증 |

로그아웃은 게임 계정 탈퇴나 인증 제공자 동의 철회와 같은 작업이 아니다. 이번 버전에 연결 해제·제공자 통지·계정 삭제까지 완료됐다고 표시하지 않는다.

## 8. 공개 전환의 완료 기준

1. 만 14세 이상 정책에 맞는 연령 확인·서버 가입 허가를 준비하고 정식 호스팅·도메인 조건을 확인한다.
2. 지정한 문의 주소의 수신·응대와 실제 데이터 처리 흐름을 확인하고, 본인과 기존 가족의 권리 행사·탈퇴·삭제 및 공개 정책을 완성한다. 필요한 청소년 가입 관련 확인은 별도로 반영한다.
3. 서비스 도메인·제공자 앱·콜백·비밀값을 설정하고 필요한 심사를 마친다.
4. 실제 계정으로 로그인·연결·로그아웃·재접속을 확인하고 기존 게임 기록이 올바르게 유지되는지 검증한다.
5. 등급분류·필요한 운영 등록·공개 접근 준비를 확인한다.
6. 준비된 범위에 맞춰 신규 가입과 공개 접근을 전환하고, 일반 방문자 입장에서 다시 확인한다.

문의 주소와 최신 만 14세 이상 정책은 확정됐으며, 구현·검증·적합한 호스팅 검토를 진행한다. 실제 사이트는 v0.5.0에 머물러 있고 v0.5.1의 원격 저장·배포 차단은 해결되지 않았다. 연락처 지정이나 지원 문의만으로 차단 해제가 보장되지는 않는다. 이 문서의 준비 항목이나 외부 승인을 완료로 추정하지 않으며, 광고·푸시는 각각의 실제 연결과 검증 전까지 비활성 상태를 유지한다. 현금 상품·결제·PG·판매 환불은 제품 범위에서 제외한다.
